# 工作效率改进探索

Status: needs-info

2026-10-19。用户希望结合当前工作台和优秀开源项目，讨论下一步值得新增的工具或功能。本轮授权为调查和访谈，尚未选择实施项目。

资料见 [工具交互研究](research-tools.md) 与 [工作流研究](research-workflows.md)。已核对第一方文档、仓库及相关代码；未安装实测外部项目，开发收益尚未通过用户真实工作样本验证。

## 已有背景

- 用户管理多个系统，过去明确提到的高频动作是查生产 Redis 账号、记排障方案、记任务并快速完成。证据见 [早期访谈](../desktop-workbench/interview.md)。
- 近期 ZIP 工具反馈强调连续快捷键粘贴、重复分片自动跳过。这支持优先讨论减少步骤，但不能据此推定需要全系统剪贴板监听或历史记录。
- 当前已具备全局资料搜索、上下文快速新建、首页常用项、台账字段复制、系统资料导出、工作回顾、工具登记与后台运行。不把这些已有能力列为待开发功能。
- 继续沿用根目录领域定义：工具为全局能力；工作任务可选关联一个系统；回顾跨度不是实际工时。工具可选取台账作为本次输入，不因此归属某个系统。
- 当前单人本地资料库、按需解锁秘密与备份迁移约定继续有效。新工具是否访问网络是单独待确认的范围。

## 暂定候选

下面是讨论建议，不是已确认需求。优先级需结合使用频率、现有替代方案和具体重复步骤调整。

| 候选 | 可验证的使用场景 | 第一版可以止于哪里 | 参考 |
| --- | --- | --- | --- |
| 排障文档模板与任务转文档 | 完成排障后，重新整理背景、过程和结论费时；以后难以复用 | 带入任务标题、系统、正文，提供现象、原因、处理、验证结构，由用户整理保存 | Trilium 模板；当前文档创建正文为空 |
| 配置与 JSON 对比 | 对比两套配置或接口响应，查找值的差异 | 先支持用户最常见格式、左右粘贴、字段路径和新增/删除/修改；不预设数组顺序无意义 | jsondiffpatch、Difftastic |
| 参数化常用命令与文本 | 找旧命令、改环境/地址/日期、检查替换反复发生 | 少量常用模板，从台账带入普通字段，补参数后预览复制 | Espanso 表单 |
| 日志与接口文本处理 | 解转义、格式化、提取字段，或整理一批 ID，要切换多次工具 | 先支持真实样本需要的操作；出现反复使用的固定流程后再保存步骤 | CyberChef、DevToys |
| 周报/月报草稿 | 工作已记录，却还需手工按系统汇总 | 选时间范围，按确定规则生成可编辑 Markdown；不推算工时 | 当前任务与回顾数据；ActivityWatch 仅作为可能的后续补记线索 |

还发现两处可以随相关功能一起改进的现有流程：

- 现有 `⌘K` 搜索尚不含工具和动作，可逐步加入“打开 ZIP”“新建排障记录”及用户主动触发的粘贴处理。借鉴 [DevToys Smart Detection](https://devtoys.app/doc/articles/extension-development/guidelines/UX/support-smart-detection.html)。
- 系统资料导出完成后，可让用户直接带入 ZIP 工具，省去切页和重新选择目录。当前导出与 ZIP 结果页没有这条连接。

持续监测可先用已有访问入口打开外部 Uptime Kuma；这一步不需要新开发。全系统文本展开、完整 API 客户端和活动采集器已有专门项目，是否内置须证明与台账、任务或文档联动带来的收益。

## 后续决策树

1. Q1 的具体流程与频率 + 现有能力核查 → 选择一个优先改进目标，并明确现在使用什么替代工具。
2. 优先目标 + Q2 的整合范围 → 确定内置新工具、增强现有模块或连接外部软件；用一条真实输入到结果的流程定义成功标准。
3. 输入类型 + Q3 的网络范围 → 决定格式、留存、处理位置、快捷入口；仅当具体场景需要时讨论秘密字段与外部调用。
4. 完整流程明确 → 核对首版边界、错误处理与验收例子，确认共同理解后才进入实施。

本轮没有形成新的领域定义或难以逆转的架构决策，因此未修改 `CONTEXT.md` 或新增 ADR。
