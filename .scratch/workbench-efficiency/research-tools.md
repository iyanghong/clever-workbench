# 工具交互与文本处理：开源项目调研

调研日期：2026-10-19。本文用于需求访谈，不构成开发承诺。只参考第一方仓库、官网和文档；未安装或实测这些项目，下面的能力来自文档与源码记录核对。未按 Star 数排名。

## 工作台的约束

工作台面向技术负责人的个人资料与工作管理；“工具”是全局能力，不归属某个系统。“常用工具”是首页快捷入口。这些定义已在 [CONTEXT.md](../../CONTEXT.md) 确立。

已有决策要求本机保存、离线使用，采用 Electron 基础，秘密字段按需解锁；普通文档正文不会自动加密。因此，新增处理功能可以接收用户主动粘贴或选择的文件，但如果要长期保存输入、历史或配置快照，必须单独说明保存范围，不能把“本地处理”等同于“内容已经加密”。参见 [本地资料库](../../docs/adr/0001-local-data-and-portable-backup.md)、[Electron 基础](../../docs/adr/0003-reuse-electron-desktop-foundation.md)、[按需加密](../../docs/adr/0004-encrypt-secrets-on-demand.md)。

## 已核实的项目能力

| 项目 | 已有事实 | 值得借鉴的部分与限制 |
| --- | --- | --- |
| [DevToys](https://www.devtoys.app/) | 跨平台桌面工具，官网列有离线的 JSON/YAML、Base64、文本对比、哈希、JSONPath、日期及 Cron 等工具。 | 一个入口承载常用小操作；它已经覆盖大量通用需求，工作台应优先补用户每天要用、需要连接台账或文档的部分。 |
| [DevToys Smart Detection](https://devtoys.app/doc/articles/extension-development/guidelines/UX/support-smart-detection.html) | 按剪贴板内容建议适用工具；点击建议工具后带入内容；也可把一个工具的输出送给另一个工具，检测可关闭。 | 减少“先知道工具名字、再找菜单、再粘贴”的步骤。工作台可选择更明确的主动粘贴触发，这是我们的产品建议，并非 DevToys 的默认行为。 |
| [IT-Tools](https://github.com/CorentinTh/it-tools) | 可自托管；新增工具有生成脚本，在独立目录创建文件并加入统一工具索引。[发布记录](https://github.com/CorentinTh/it-tools/releases) 包含收藏、命令面板、文本比较、JSON/XML 转换、正则测试等功能。 | 借鉴轻量模块登记和统一操作外观。工作台已建立内置工具登记与首页常用工具，不必再造一套框架或移植整站。 |
| [CyberChef](https://github.com/gchq/CyberChef/blob/master/README.md) | 输入、输出与有顺序的操作步骤分开；支持拖入文本/文件、自动或手动处理、逐步检查、保存处理步骤；处理在客户端完成，可本地运行。 | “保存一组重复操作”比堆几十个独立转换按钮更有复用价值。完整 CyberChef 的范围很大，首版可仅覆盖已经确认的固定步骤。 |
| [jsondiffpatch](https://github.com/benjamine/jsondiffpatch) | JavaScript 对象深层比较，支持差异可视化和 JSON Patch；数组中按对象身份匹配需要提供 `objectHash`，否则按位置匹配。 | 适合评估 JSON 字段差异能力，但不是现成的整个配置比较产品；数组“顺序变了”还是“内容变了”要给出明确规则。 |
| [Difftastic](https://difftastic.wilfred.me.uk/) | CLI 以语法结构比较文件，可减少格式变化带来的噪声；支持 JSON、YAML 等格式。 | 可借鉴“看实际变化”的展示。它的[文档](https://difftastic.wilfred.me.uk/tricky_cases.html)明确说明顺序变化仍有意义、解析出错时退回行比较；不能把语法比较宣称为完整的业务语义比较。 |

CyberChef 允许用 URL 携带处理步骤和输入，属于该项目已有能力。工作台没有必要照搬携带原始输入的分享链接；用户若需要分享，可以另行讨论只保存处理步骤，或经确认保存处理结果。这个建议来自工作台现有秘密保护边界。[CyberChef 深链接说明](https://github.com/gchq/CyberChef/blob/master/README.md#deep-linking)

## 建议拿给用户讨论的三个候选

下面是结合工作台情境做出的推断。排序取决于真实使用频率，尚未获得用户确认。

### 1. 配置与 JSON 对比

情景：测试环境正常、生产环境异常，用户从两处复制配置或接口返回，想快速看到端口、地址、开关、超时等值哪里不同。也可以比较同一接口修改前后的返回。

建议首版提供左右粘贴或选择两个文件、字段路径定位、只看差异、明确的新增/删除/修改，以及原文与结构视图切换。先确认常见格式：如果主要是 JSON，就先做好 JSON；如果主要是 Java 配置，则需要再具体讨论 YAML、Properties 和重复键的处理。保存结果到技术文档可以作为后续连接点。

借鉴 jsondiffpatch 的字段级比较与 Difftastic 的减少格式噪声。不能直接认定“排序后完全相等”：数组顺序、重复键、字符串中的空格可能有业务含义。第一步以比较和解释为主，不必顺带实现配置下发、远程拉取或自动合并。

### 2. 日志与接口文本处理

情景：从聊天或日志里拿到一段转义的 JSON，需要解转义、格式化、提取某个字段；或收到一批 ID，需要去空行、去重并变成逗号列表。用户现在可能要打开多个网页或反复写临时脚本。

建议把已确认的高频操作放到同一输入/输出界面，例如 JSON 格式化与字段提取、URL/Base64 解码、按行筛选/去重。每一步保留可查看的结果，支持撤回；如果某串步骤每周都会做，再允许命名保存，例如“日志 payload 解码”。保存处理步骤和保存原始数据应分开。

借鉴 CyberChef 的操作顺序与复用，DevToys 的输出传递。不要先开发通用可视化脚本平台；也不要默认把所有输入判为编码内容并替用户连环转换。先用用户过去一周的两三个实际例子确定操作范围。

### 3. 用快捷键把内容交给合适的工具

情景：用户已经复制一段 JSON 或 ZIP 文本分片，希望立即处理，减少回到首页、寻找工具、切换子页面的操作。

建议在现有搜索/命令入口加入“粘贴并处理”，由用户主动触发后识别内容并列出明确动作，例如“打开 JSON 格式化”“加入 ZIP 还原分片”；工具输出也可直接交给下一个适用工具。工具数量较少时，这项可与第一个新增工具一起做小范围验证。

这是工具入口的改进，不必另做一个工具页面。用户此前要求 ZIP 支持连续快捷键粘贴，是支持这个方向的实际行为证据。DevToys 提供交互参考，但全局快捷键、后台监听剪贴板、保存剪贴板历史是三个不同范围，不能由“快捷键方便”推导为全都需要。

## 需要用户决定的分歧

1. 过去一周，最常重复的是对比配置、整理日志/接口返回，还是查找账号和资料？每项给一个实际例子，才能判断开发收益。
2. 首个文本工具更偏“临时处理完就关闭”，还是要保存原文和结果继续分析？后者涉及本地留存、秘密内容与资料归属。
3. 配置比较最常见的两种格式是什么？数组换序是否通常表示实际变化？这些会决定比较规则，不能用一个“智能对比”开关掩盖。
4. 快捷操作是在工作台窗口内按键即可，还是必须在其他应用中按全局快捷键唤出？是否真的需要历史记录，应单独回答。
5. 如果已有 DevToys、编辑器或终端能顺手完成通用操作，工作台新增能力必须省掉哪一步？若没有明显收益，可先连接现有工作台的台账、工作任务与技术文档流程。
