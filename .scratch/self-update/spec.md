## Problem Statement

用户希望在 Clever Workbench 内发现并安装 GitHub 上的新版本，避免自行寻找 Release、下载安装包、退出并替换应用。体验参考 sub2api 的版本徽标和更新面板。

更新对象是 Clever Workbench 自身，不是 sub2api 服务。更新来源是正式 Release，不是最新 Git 提交。用户不采用 Apple Developer ID 签名和公证，但希望正常情况下由更新助手自动替换当前应用并重新启动；遇到系统权限或安全拦截时接受人工处理。

工作台持有本地技术台账、工作任务、文档、附件和凭据，符合安装条件的更新必须在替换前保存并备份，不能以更新成功为由牺牲资料完整性。

用户还实际遇到“源码已经合并，但正在打开的应用没有更新入口”：系统中运行的仍是未包含更新器的 v0.1.0 安装包。源码分支、已发布版本和当前运行的应用必须分清，首次启用更新器也需要一条明确的补装路径。

日常使用时，用户希望把手动检查集中到设置，仅在确有新版本时于“个人工作台”右侧提示更新。更新弹窗需要清晰展示版本、进度和可执行操作，并适配深浅主题和小窗口，避免让次要说明挤占主要信息。

用户还发现更新弹窗打开后无法用鼠标关闭：关闭图标看得见，点击却没有作用。窗口必须允许用户可靠地返回工作台；仅按 Esc 或自动化点击能够关闭，不能证明实际鼠标路径可用。

本轮又出现应用已经放在“应用程序”，点击“重启并更新”仍提示“不能直接更新磁盘映像中的应用”。实际运行的是 macOS App Translocation 创建的只读隔离副本，原位置可写不代表当前运行位置可替换。原提示混淆了隔离运行与磁盘映像，位置检查还发生在完整备份之后，重复尝试会先做无用的准备工作。界面额外显示的 IPC 技术错误前缀进一步遮蔽了可操作的原因。

应用包替换完成后，还可能受到 Gatekeeper 拦截而没有可见窗口。发起打开请求、出现进程或点击系统按钮，都不能证明新版本可用。用户需要知道安装是否已经完成、是否仍需系统授权，以及当前运行状态与“上次更新超时”之间的区别。

用户还要求更新文件随版本迭代，成功安装后清理旧应用和下载暂存，避免长期积累本地版本副本。下载校验完成时应主动询问立即重启还是稍后重启，不能要求用户自行打开长更新说明并滚动寻找操作。

## Solution

首版面向 macOS Apple Silicon 的正式安装版。手动检查只放在设置的关于区域，同时展示当前版本、详细状态、更新历史和历史版本入口。左侧栏顶部“个人工作台”右侧仅在发现新版本后显示“更新”按钮；点击展开当前版本、目标版本、发布时间、更新说明和下载动作。下载、校验和等待安装时保留按钮，下载失败但仍有可重试的目标版本时也保留。无新版本、检查尚无结果或仅检查失败时不显示该按钮，侧栏底部不再常驻版本和检查入口。

更新面板依次呈现应用身份与当前版本、带说明的状态、下载进度、目标版本说明和当前可执行操作。更新来源、访问权限与本地更新历史默认折叠。长说明可滚动，标题关闭按钮和底部操作保持可达；界面沿用工作台主题、焦点和可访问性约定。

在面板可交互阶段，鼠标点击右上角 × 与按 Esc 均可关闭，重新打开仍可查看当前状态。关闭只结束查看面板，不取消下载、不退出工作台，也不请求安装。焦点返回仍存在的触发按钮。真实鼠标不能被弹窗下方工具栏的窗口拖拽区域截走；安装已经进入保存、备份或替换阶段时继续遵守原有操作保护。

应用启动时及运行期间每 30 分钟静默检查固定仓库的正式 Release。用户点击下载后显示进度，校验成功后主动弹出独立的重启选择，提供“立即重启并更新”和“稍后重启”。此时更新包已准备好，应用尚未被替换。用户选择立即重启后，先检查当前运行位置是否可安装，通过后才保存、冻结写入、创建完整加密备份和安全退出；独立助手在当前运行应用所在位置替换完整应用包，再启动新版本。安装未完成不能显示成功；新版本通过启动健康确认后才记录更新成功。

选择稍后、关闭或按 Esc 均继续当前工作，不执行安装；同一次下载不重复弹出。准备好后点击品牌旁的更新按钮可直接重新打开重启选择。重启提示不承载长版本说明，主要按钮在窄窗口中直接可见。新版健康确认后清理安装助手持有的旧应用副本及本次 ZIP 和解压目录；完整加密备份、用户资料和更新日志保留。失败或健康未确认时保留恢复材料，清理失败单独记录，不伪报文件已删除。

安装位置不合格时立即停止准备，保持工作台可用，清楚区分系统只读隔离、应用包位置无效、所有权不符及目录不可写。给出“退出应用、使用正式安装包、通过 Finder 安装到应用程序、重新打开并检查版本”等对应步骤。设置与更新面板显示可操作的原因，去除 IPC 调用包装，不把所有失败都解释为正在运行磁盘映像。

人工恢复使用已校验的正式 DMG，在正常退出后通过 Finder 替换应用，并保留既有资料、备份和旧应用。若 macOS 明确阻止打开，由用户针对当前应用完成系统提供的“仍要打开”及必要的本机身份验证；系统没有显示验证窗口时，不能假定授权已经完成。恢复后确认实际运行版本、正常安装位置、窗口、资料和更新检查。当前已是最新版本时仍可保留此前失败的历史记录，两者分别说明当前状态和过去事务的结果。

不含更新器的旧安装版需要先人工安装一次包含更新器的正式版本。补装时正常退出旧应用、保留现有资料目录和旧应用副本，再验证新版实际运行的版本、更新入口及检查结果。之后从应用内完成检查和后续更新。合并或拉取源码不会替换已安装应用；成功读取正式版本且其版本号不高于当前运行版本时，在设置中显示“已是最新版本”并保留手动检查，品牌旁不显示更新按钮。

以两个真实安装包验证无 Developer ID 条件下的替换、重启和失败恢复。正常路径由助手自动替换并尝试启动新版；若 macOS 阻止启动、将应用隔离运行或新版本未能初始化，进入明确的人工处理流程。助手最多等待 60 秒取得有效健康回执，无法确认时保留旧应用、加密备份和日志，并打开恢复说明所在目录。自动安装与重启是可执行的操作，不承诺在所有未签名分发环境中无人值守启动成功。

本机实验已验证本地助手的正常替换重启和恢复，以及完整应用受系统限制时的人工处理路径。随后从同一私有仓库实际已发布的 v0.1.1 经真实网络更新至 v0.1.2，验证下载、备份恢复和原位替换。带 quarantine 的完整新版未产生健康启动回执，结果为明确人工处理，不能据此宣称健康的无人值守升级成功。证据见[安装验收](acceptance.md)。

本机后来完成的 v0.1.0 首次补装已正常启动 v0.1.2，且实际更新窗口显示“已是最新版本”。这是另外一次安装和入口验证，其来源与安全属性条件不同，不能将此前真实自动升级实验的人工处理结果改写为健康成功。

## User Stories

1. 作为工作台用户，我希望随时在设置中查看当前应用版本，以便确认自己使用的版本。
2. 作为工作台用户，我希望启动后自动检查更新，以便及时知道正式版本发布。
3. 作为工作台用户，我希望长时间使用时每 30 分钟检查一次，以便无需重启也能收到更新提示。
4. 作为工作台用户，我希望在设置中手动检查更新，以便主动确认发布状态。
5. 作为工作台用户，我希望只有发现新版后才在品牌副标题右侧显示更新按钮，以便发现更新且平时界面简洁。
6. 作为工作台用户，我希望看到当前版本、目标版本、发布时间和更新说明，以便决定是否升级。
7. 作为工作台用户，我希望仅下载正式稳定版，以便避免意外安装测试版本。
8. 作为工作台用户，我希望点击后才下载，以便控制网络流量。
9. 作为工作台用户，我希望看到下载进度和错误原因，以便知道是否需要重试。
10. 作为工作台用户，我希望下载期间继续使用工作台，以便不中断当前工作。
11. 作为工作台用户，我希望下载完成后自行选择重启时机，以便避免突然退出。
12. 作为工作台用户，我希望更新包经过来源、完整性和架构检查，以便安装正确的应用。
13. 作为工作台用户，我希望损坏或不兼容的更新包被拒绝，以便保留可用版本。
14. 作为工作台用户，我希望退出前所有编辑和图片导入完成保存，以便保留最新工作。
15. 作为工作台用户，我希望更新前生成完整加密备份，以便在出现数据兼容问题时恢复。
16. 作为工作台用户，我希望保存或备份失败时停止安装，以便先解决问题。
17. 作为工作台用户，我希望更新我正在运行的应用副本，以便不会更新错误位置。
18. 作为工作台用户，我希望应用自动退出、完成替换并重新打开，以便减少手工安装操作。
19. 作为工作台用户，我希望不可写或只读位置给出明确提示，以便知道如何继续。
20. 作为工作台用户，我希望系统授权或安全检查由系统正常处理，以便无需关闭系统保护。
21. 作为工作台用户，我希望替换失败时恢复旧应用，以便继续工作。
22. 作为工作台用户，我希望新版本经过版本、数据库、窗口和通信检查，以便更新成功具有实际含义。
23. 作为工作台用户，我希望启动失败时仍能找到旧安装包、备份和恢复说明，以便自行恢复。
24. 作为工作台用户，我希望恢复过程不静默覆盖更新后产生的数据，以便避免二次损失。
25. 作为工作台用户，我希望查看最近 30 次更新记录，以便排查失败阶段。
26. 作为工作台用户，我希望离线、限流或没有 Release 时仍可使用工作台，以便更新服务不影响本地业务。
27. 作为开发者，我希望开发模式明确不支持安装更新，以便开发目录不被替换。
28. 作为维护者，我希望发布流程校验版本并生成完整资产和校验信息，以便客户端有稳定的更新协议。
29. 作为维护者，我希望重复点击、多个实例和意外退出不会产生并发安装，以便安装过程可恢复、可诊断。
30. 作为工作台用户，我希望新版在应用代码启动前受阻时也能得到有限时的处理结果，以便不会一直等待没有进展的更新。
31. 作为工作台用户，我希望安装后仍保留下载包的 macOS 安全属性，以便由系统正常判断应用来源。
32. 作为工作台用户，我希望恢复说明与应用分开保存，以便新版无法打开时仍能找到旧包、备份和日志。
33. 作为工作台用户，我希望暂存失败后可以在解决磁盘或权限问题后重试，以便不被失败残留永久阻挡。
34. 作为工作台用户，我希望更新记录损坏时仍能打开本地工作台，以便维护更新功能不影响日常工作。
35. 作为维护者，我希望清楚区分本地测试响应、真实安装包和公网 Release 验收，以便不会将错误路径测试通过误认为正式升级成功。
36. 作为工作台用户，我希望应用展示实际运行安装包的版本，以便确认自己是否已安装包含更新器的版本。
37. 作为旧版工作台用户，我希望有一次人工补装更新器的明确路径，以便之后使用应用内更新。
38. 作为工作台用户，我希望首次补装前正常退出应用并保留原有资料，以便换用新安装包后继续工作。
39. 作为工作台用户，我希望首次补装后能在设置中看到当前版本和检查结果，以便确认新功能已经可用。
40. 作为工作台用户，我希望没有新版本时仍能在设置中查看版本并手动检查，以便确认更新状态，侧栏仅在有更新时提示。
41. 作为私有仓库用户，我希望更新复用本机 Git 已保存的读取权限，以便继续使用原仓库而无需共享内置令牌。
42. 作为私有仓库用户，我希望缺少读取权限时得到配置登录的提示，以便不会将授权失败误认成没有新版本。
43. 作为正在使用工具的用户，我希望归档或还原任务未完成时停止准备更新，以便不会因退出安装而中断处理。
44. 作为维护者，我希望区分主分支代码、正式 Release 和本机安装结果，以便准确说明各项功能的交付状态。
45. 作为维护者，我希望记录云端未运行和人工完成发布的实际情况，以便不会将本机验证误报为完整云端发布成功。
46. 作为工作台用户，我希望下载中和等待安装时仍能从品牌旁返回更新面板，以便继续查看进度或选择安装时机。
47. 作为工作台用户，我希望更新面板清楚区分当前版本、目标版本和当前状态，以便判断下一步该做什么。
48. 作为工作台用户，我希望状态有文字、图标和适合主题的视觉提示，以便不必仅凭颜色理解结果。
49. 作为工作台用户，我希望下载同时显示百分比和已下载／总大小，以便了解实际进度。
50. 作为工作台用户，我希望长版本说明可以单独滚动，以便阅读内容时仍能找到主要操作。
51. 作为工作台用户，我希望右上角关闭按钮在长内容和小窗口中保持可达，以便随时结束查看并继续工作。
52. 作为工作台用户，我希望鼠标点击关闭按钮能够真正关闭弹窗，以便不会被工具栏拖拽区域困在面板里。
53. 作为键盘用户，我希望按 Esc 关闭后焦点返回仍存在的更新入口，以便继续用键盘操作。
54. 作为工作台用户，我希望反复打开和关闭更新面板仍然正常，以便稍后再次查看更新内容。
55. 作为工作台用户，我希望关闭面板后正在进行的下载继续，以便可以边工作边等待。
56. 作为工作台用户，我希望下载失败且目标版本仍有效时保留更新入口和重试下载动作，以便恢复更新。
57. 作为工作台用户，我希望未找到兼容版本或仅检查失败时不出现新版按钮，以便不会把错误误认为已有可安装更新。
58. 作为工作台用户，我希望更新面板适配深浅主题，以便在当前工作台外观中清楚阅读。
59. 作为小窗口用户，我希望更新面板没有横向溢出，关闭、下载和安装动作仍可操作，以便无需先放大窗口。
60. 作为工作台用户，我希望更新来源与访问权限默认折叠、需要时可展开，以便先关注版本与状态。

65. 作为代码贡献者，我希望本轮提交作者和提交者使用我确认的 ikuku-tt 身份、提交说明使用中文，以便仓库协作者正确理解改动来源。
66. 作为维护者，我希望明确区分源码推送、本机预览与正式 Release，以便准确判断哪些用户已能得到界面调整。
67. 作为工作台用户，我希望系统隔离运行时得到准确说明，以便理解应用已经放入“应用程序”仍无法原位更新的原因。
68. 作为工作台用户，我希望点击重启更新后先检查安装位置，以便无法安装时无需等待保存、冻结或新建完整备份。
69. 作为工作台用户，我希望看到目录权限和应用所有权问题的具体处理方向，以便选择可写的安装位置或人工安装。
70. 作为工作台用户，我希望重复尝试不合格的安装位置时不会不断生成无用备份，以便减少等待和磁盘占用。
71. 作为工作台用户，我希望安装错误去掉 IPC 调用包装，以便直接阅读原因和下一步操作。
72. 作为工作台用户，我希望预检失败后工作台仍可编辑和正常退出，以便继续工作并自行处理安装问题。
73. 作为工作台用户，我希望恢复指引依据实际运行位置，以便不会因为存在同名应用而更新错误副本。
74. 作为工作台用户，我希望区分“应用包已替换”与“新版已正常打开”，以便系统尚未放行时不会被告知更新成功。
75. 作为工作台用户，我希望通过 macOS 对当前应用的正常打开授权完成恢复，以便继续使用系统的来源与安全检查。
76. 作为工作台用户，我希望身份验证在系统窗口中完成，以便管理员密码和 Touch ID 不进入工作台、聊天或诊断日志。
77. 作为工作台用户，我希望没有可见系统验证窗口时得到如实的状态说明，以便不会反复等待一个并未确认出现的窗口。
78. 作为工作台用户，我希望人工重装后保留原有资料代次、主密码配置和备份位置，以便继续使用原来的工作空间。
79. 作为工作台用户，我希望恢复后从实际安装窗口确认版本和检查结果，以便知道新版本确实已运行。
80. 作为工作台用户，我希望当前“已是最新版本”与上次更新的失败记录分开显示，以便历史超时不会被误认为当前安装失败。
81. 作为维护者，我希望单独记录人工恢复成功的证据，以便既不丢失恢复结果，也不覆盖原自动升级事务的失败结论。
82. 作为维护者，我希望区分已完成的回归与尚未验证的无人值守升级路径，以便后续开发与发布不会重复实施或夸大交付结果。
83. 作为工作台用户，我希望新版健康启动后删除旧应用及本次下载暂存，以便更新文件不会随正常升级持续积累。
84. 作为工作台用户，我希望更新失败时仍有旧应用和恢复材料，以便不因过早清理失去恢复机会。
85. 作为工作台用户，我希望下载和校验完成后立即看到重启选择，以便不用寻找更新面板或滚动长说明。
86. 作为工作台用户，我希望选择稍后重启能继续工作，且同一次下载不反复提醒，以便自行安排安装时间。
87. 作为工作台用户，我希望稍后点击更新按钮能直接重新选择重启，以便已准备好的更新随时可安装。
88. 作为工作台用户，我希望完整加密备份与更新日志不随应用清理被删除，并能看到清理失败结果，以便准确了解恢复材料与磁盘占用。

## Implementation Decisions

### 更新源与发布

- 固定仓库为 iyanghong/clever-workbench。客户端不提供任意更新源配置，也不内置发布凭据。早期针对 sub2api 部署和 Git 快进更新的讨论已被本规格取代。
- 更新来源兼容同一仓库的公开与私有读取。历史任务 07 使用私有仓库权限，后续发布时确认仓库已公开；客户端不负责改变仓库可见性。私有读取复用每台电脑 Git 凭据助手中已有的 GitHub HTTPS 权限，凭据仅在主进程内存使用，不新建凭据存储，不返回页面或日志。授权仅发给固定仓库的 GitHub API，资产重定向后不携带授权；公开读取可匿名进行。
- 只接受已发布、非草稿、非预发布的 vX.Y.Z Release；使用可靠的语义版本比较，目标必须高于当前版本。没有 Release、没有兼容资产和检查失败分别展示，不能统一显示“已是最新”。
- 首版支持 macOS arm64 安装版；开发模式明确禁用安装功能。
- 自动安装使用包含完整应用包的 ZIP；DMG 保留为首次安装和人工恢复资产。两种资产均由同一发布版本生成，并提供 SHA-256 清单。ZIP 取代此前手动 DMG 安装方案中的安装载体。
- 发布时校验应用版本与 tag 一致，运行已有必要验证，上传完整资产与校验信息后再公开 Release。维护者凭据只用于发布环境。
- 草稿上传完成后以 Release 唯一 ID 读取资产元数据并核对，不依赖按标签读取草稿的接口。验证通过后才正式发布；不得覆盖已经发布的版本。
- 云端因账单或额度等原因未能执行时，维护者已授权的本机发布仍需验证应用与 tag 对应、完整测试、实际包、远程大小和 SHA-256 清单。记录构建来源及人工完成的步骤，不能将云端失败或未执行记为通过。
- 不引入 Developer ID 或公证要求；可保留现有 ad-hoc 打包方式。采用自制助手，不将 Electron 标准自动更新器的签名能力假定为可用。
- 维护者的双击发布流程使用独立规格，当前发布平台收敛为 macOS arm64。正式构建只纳入远端已推送源码；本轮独立的未提交发布入口改动保留在本地，不混入更新修复或正式资产。
- 源码与版本提交的作者、提交者均取当前生效的本地 Git 配置，提交前后核验身份与中文说明。本轮身份为用户明确确认的 ikuku-tt，不用仓库所有者、应用作者字段或执行工具身份替代；不重写已发布提交和标签。

### 实际运行版本与首次补装

- 当前版本以正在运行的安装包为准；源码、开发构建和已发布 Release 的版本分别记录。主分支已合并不表示系统中的旧应用已经替换，开发模式也不能用来证明安装版自动检查可用。
- 已确认历史 v0.1.0 不含更新器，需要一次人工补装；首次支持更新器的正式基线为 v0.1.1。正常退出旧应用后替换原应用位置，保留旧应用副本和现有资料目录，再从新进程验证更新入口。
- 补装使用可信正式资产；复用本机已有安装包时，内容必须匹配正式资产大小和 SHA-256，并核对应用身份、版本、架构及原生包完整性，不能仅凭文件名或版本号认定它与发布资产一致。保留原有安全属性，不修改系统保护。
- 首次补装与应用内安装事务分别记录。旧应用副本保留不等于已创建完整加密资料备份；应用内“重启并更新”的备份前提保持不变。
- 主分支后续变更经更高版本的正式 Release 才进入客户端更新范围。已发布同版本的安装包不因后续合并而改变，也不自动分发尚未发布的 Git 提交。
- 人工恢复也必须核对正式资产、包完整性和实际运行位置。通过 Finder 完成正常安装并保留下载来源的系统安全属性；原安装包、下载的正式包和正在运行的进程分别确认，不以“某处存在同名应用”代替结果验证。

### 更新协调与接口

- 主进程中的单一更新协调器拥有状态；页面通过既有类型化桌面桥获取快照、订阅变化、检查、下载和请求安装。页面不能提交任意 shell 命令、可执行路径或下载地址。
- 状态至少区分不支持、检查中、无更新、有更新、下载中、待安装、保存与备份中、替换中、等待启动确认、成功、失败和需要人工处理。
- 首次启动检查与每 30 分钟检查仅在应用运行期间发生，不创建常驻系统定时任务。缓存、并发合并和限流退避避免重复请求；网络失败不影响业务使用。
- 手动检查入口只在设置中提供，品牌旁更新面板只负责查看、下载、重试下载与安装。品牌旁按钮根据已有协调器的目标版本与可继续更新状态显示；当前已是最新版本、无 Release、无兼容包、开发模式和未获取目标版本的错误均不显示。下载、校验、等待安装及仍有目标版本的下载失败保留入口，关闭面板不会取消更新。自动检查调度不依赖按钮是否可见。
- 启动健康确认结束后恢复自动检查调度，同时保留上次更新的结果摘要。更新记录读取或写入失败时限制在线更新并展示原因，不能因此阻止本地工作台打开。
- 同一应用安装位置同一时间只允许一次安装事务。更新助手拥有足够独立的运行条件，主应用退出或被替换后仍能完成操作。
- 下载仅接受固定仓库的 HTTPS Release 资产，并约束重定向、大小、架构和包身份。校验文件缺失或不匹配必须失败。SHA-256 是完整性检查，不宣称它等同于开发者身份签名。
- 原生 Electron 下载必须能暴露单跳重定向并交给协调器验证，不能假定其手动重定向行为等同 Node.js。已采用原生请求读取响应头后终止探测、正文通过禁止重定向的原生流读取；不将大安装包排入自建无界事件队列。两次请求间若目标转为其他重定向则安全失败，授权不会由底层自动转发至 CDN。
- 解压不能逃逸暂存目录；拒绝恶意路径和异常包结构，同时保留合法 macOS bundle 所需的权限及内部链接。安装前核对应用身份、架构和目标版本。
- 解压完整应用包时使用原始文件读写能力，避免 Electron 对 ASAR 的特殊处理影响新包写入；不得通过全局关闭 ASAR 语义改变正在运行的应用行为。

### 更新入口与面板交互

- 品牌旁提示与设置详情使用同一更新协调器的快照及状态订阅。提示位置固定在品牌副标题右侧，不以静态版本号、失败提示或最新 Git 提交代替可用新版判断，不建立另一份独立版本状态。
- 设置的关于区域是手动检查的唯一界面入口。品牌旁按钮只打开详情，面板提供当前可执行的下载、重试下载、重启更新和历史版本访问；打开详情不会额外触发一次手动检查。
- 只有存在已验证的更高目标版本且更新可继续时显示品牌旁按钮。普通检查失败、无正式版本、不兼容、已是最新、开发或不支持状态均隐藏。下载、校验、待安装及仍有目标版本的下载失败保留按钮；背景检查调度保持不变。
- 更新详情和设置关于区域复用同一呈现逻辑，按场景决定是否展示检查动作。操作可用性由协调器状态决定；忙碌时禁用冲突检查，待安装时以重启更新为主要动作，不提前退出或安装。
- 信息分为应用身份、状态说明、进度、版本说明、辅助信息及操作区域。下载进度显示实际字节与可计算的百分比；上次更新结果、错误和可重试时间保留明确文字，不以装饰性成功状态覆盖失败信息。
- 复用既有图标、主题语义色与共享对话框，支持深浅主题、减少动态效果和键盘焦点。品牌样式只作用于品牌本身，避免改变更新弹窗内的版本文字与进度排版；本轮不新增依赖、数据结构或桌面桥接口。
- 版本说明按纯文本呈现，长内容在受限区域滚动；关闭按钮和主要操作在小窗口保持可达。来源与私有仓库权限说明、本地历史默认折叠，历史版本仍通过已有受控外链入口访问。
- 共享对话框必须显式排除底层原生窗口拖拽区域，包含标题和关闭控件所在范围。原生对话框出现在视觉顶层，并不自动证明实际鼠标能够点击，不能只依靠层级数值或辅助功能触发处理本问题。
- 面板关闭不改变更新协调器任务，也不等同取消下载或安装。重新打开读取当前状态；若状态变化使品牌按钮消失，已打开的面板仍可显示结果并关闭。关闭时只向仍存在的触发控件归还焦点，不指向失效节点。
- 安装失败的用户提示保留主进程提供的具体原因，去除 Electron IPC 远程调用包装。原生错误消息可能没有外层错误前缀，不能只处理某一种字符串形式；系统拦截、位置不符和备份失败不能被统一改成无原因的“更新失败”。
- 下载校验完成后由全局更新入口显示一次独立的重启选择，替换正在打开的更新详情，避免两个更新弹窗叠放。没有目标版本、仍在下载或校验时不显示。稍后、关闭和 Esc 不发送安装请求；相同准备状态重复推送不再次提醒，新的下载完成后可再次提示。
- 重启选择只展示目标版本、保存与备份说明和两个操作，正文可滚动而操作区保持可见。选择立即重启继续使用同一安装接口，准备阶段遵守写入冻结及操作保护，失败后可以继续工作和重试。品牌旁的待安装入口直接回到重启选择，设置中继续保留完整说明。

### 安装位置预检

- 已下载并校验的更新收到安装请求后，先执行位置预检，再进入安装资格检查、保存协调、写入冻结和本次完整备份。预检失败不得启动安装助手、退出应用或新增完整备份；页面保持可用并显示原因。
- 目标从当前进程实际使用的可执行文件确定。App Translocation 的只读隔离位置必须明确拒绝，不能将其重映射到猜测的原位置，也不能因“应用程序”中存在另一个副本就改为更新该副本。
- 要求目标为完整应用包目录、不是符号链接、属于当前用户，并且父目录可写。应用结构或所有权异常、系统只读隔离和权限导致的不可写使用对应提示；不通过抬高权限、修改所有权或清除系统隔离属性解决。
- “位于磁盘映像”不能仅靠隔离路径或目录名称推断；普通目录不可写时说明写权限问题，系统隔离运行时说明实际运行方式和 Finder 安装步骤。
- 独立助手启动前复用同一位置校验，再检查完整备份和事务准备条件，避免只依赖安装开始时的早期结果。保留助手自身的安装目标与包身份校验。
- 预检是现有安装协调器的内部前置能力，主进程提供真实运行位置和文件系统检查。渲染层的安装请求保持原有无路径参数契约，不新增测试专用生产接口、数据库字段或用户配置项。

### 保存、备份与替换

- 安装位置预检通过后，“重启并更新”复用既有退出前保存协调，等待编辑、图片导入和相关业务操作完成；不能绕过正在进行的恢复、主密码轮换或导出。
- 工具的后台归档或还原尚未完成时，安装资格检查提示等待并拒绝准备更新。保存协调结束后再次检查，冻结新业务写入后才进入备份与安装，不能把启动工具操作的接口已返回当作后台任务已完成。
- 保存完成后生成与本次安装关联的完整加密备份，包含资料和附件；不能因当日已有自动备份或没有变更而跳过本次要求。
- 依照现有完整备份约定，未设置主密码、备份目录不可写或空间不足时，停止安装并提示处理。不得生成未加密的替代备份。
- 从准备备份到退出期间阻止新业务写入，确保备份对应最终保存状态。保存或备份失败恢复正常使用状态，旧应用保持原位。
- 安装准备所需的事务关联和历史持久化操作必须在助手启动前完成。准备失败时不得留下等待普通退出后继续安装的助手。
- 自动更新当前实际运行的应用包位置。DMG、只读挂载或无法写入的位置停止替换并给出安装指引；不偷偷转移到另一安装位置。
- 助手确认主应用及影响替换的进程退出后，使用同一文件系统的暂存与重命名步骤替换完整应用包。整项操作不假定多次重命名构成一个原子事务，需记录阶段以处理崩溃或中断。
- 在新版健康确认前暂时保留上一版本应用包，并明确提供备份位置。替换失败优先恢复旧包；若恢复也失败，保留恢复材料及可读错误，不删除唯一可用副本。
- 收到匹配版本的成功健康回执后，在安装锁仍由当前助手持有期间删除其确认归属的旧应用副本和本次下载目录，包括 ZIP 与解压应用。只处理预期身份、当前用户所有且未被占用的旧应用，以及更新暂存根下本次私有下载目录；拒绝符号链接、越界或来源不明的清理目标。
- 成功清理不提供长期本地应用版本回滚；需要历史安装包时仍通过 Release 页面获取。完整加密资料备份、当前资料及事务日志不属于清理范围。清理结果另行写入历史，已删除的旧应用不再显示定位入口；清理受阻不改写健康成功，也不能冒充清理成功。此前失败或人工恢复的历史结论保持不变。
- 替换前暂存失败或可处理的中断应清理本次事务明确拥有的暂存包，允许再次尝试；未知目录和已经进入替换阶段的恢复材料不能盲目删除。
- 新应用启动前不能自动移除 quarantine、关闭 Gatekeeper 或绕过系统授权。复制完整应用包时显式保留并核对源包根目录的 quarantine，存在该属性但无法读取、复制或核对时停止替换。遇到系统拦截进入需人工处理状态，不虚报完成。

### 健康与恢复

- 安装事务记录起止版本、应用位置、备份引用和启动确认标识，位置独立于被替换的应用包。
- 新进程必须确认实际目标版本、数据库打开与迁移、主窗口加载、主进程与页面通信成功，才能将事务标记成功。健康检查有有限等待时间，不以进程存在代替健康。
- 启动确认只关联受信任的本机资料目录中归属于本次安装的事务。App Translocation 导致运行位置不符合预期时记录人工处理，不能仅因版本号正确而判定成功。
- 独立助手在主程序之外最多等待 60 秒，校验健康回执的归属、结构和目标版本。超时、回执无效或明确要求人工处理时记录相应阶段，不无限停留在等待状态。此能力仅作有限时诊断，不负责自动回退数据库。
- 安装前在应用包之外生成可读恢复说明，列出当前和上一应用位置、完整加密备份和日志位置。新版尚未初始化便受阻时，助手也应能打开该恢复目录。
- 启动失败或超时保留诊断、旧应用和数据备份，提供恢复指引。首版不承诺新版本完全无法启动后的无人值守业务恢复。
- 安装替换阶段的自动恢复不等于数据库回退。新版本可能已执行迁移时，不自动覆盖数据库，也不盲目启动不兼容的旧版本访问新数据。
- 历史版本入口用于人工恢复。此前关于“成功更新后应用内一键降级”的提议已被手动恢复边界取代。
- 更新历史保留最近 30 次更新事务，包含时间、起止版本、阶段耗时、最终结果和脱敏错误；静默检查不反复挤占更新历史。
- Gatekeeper 的打开限制与 App Translocation 的只读运行分别判断。前者按 macOS 实际提供的应用打开流程处理，后者按正常 Finder 安装和重新启动处理；不能仅凭进程存在、启动请求已发出或按钮点击已执行判定授权或启动完成。
- 系统要求的 Touch ID 或管理员密码只在本机系统界面完成，与工作台主密码及完整备份密码的用途分开。辅助操作必须取得用户对该应用打开授权的明确同意，不将其扩展为关闭系统保护、修改全局应用来源或清除安全属性。
- 看不到系统验证窗口时先核实实际界面和进程状态，不能根据认证后台组件存在而宣称用户已经看到提示；不能无限重复启动或根据工具点击返回成功改写事务结果。
- 人工恢复确认正常安装位置、实际版本、窗口可用和原资料仍可加载；保留原自动升级的超时或人工处理记录，并另记本次恢复结果。当前版本检查可以显示“已是最新版本”，同时展示上次失败摘要；二者不能相互替代。

## Testing Decisions

以下测试边界已获用户确认，并在 2026-10-20 本次 to-spec 中再次明确回复“符合，沿用这些边界”。以已安装应用的更新入口为主要验收边界，安装协调器失败保护和真实 macOS 授权后恢复作为必要补充，不增加测试专用的生产接口。

1. **主要行为边界：应用更新操作接口。** 沿用现有类型化桌面桥，围绕检查、下载、安装请求和状态订阅验证完整行为；主进程协调器是这些行为的单一入口。替换网络、时间和安装执行等外部依赖以稳定模拟异常，不为每个内部函数建立独立测试契约。原生 HTTP 302、凭据隔离和真实 ZIP 验证仍通过同一检查／下载行为进入，补足 Node.js 模拟不能覆盖的运行时差异。
2. **真实系统边界：两个打包应用之间的升级。** 沿用已有可针对安装版启动的桌面测试入口，使用隔离资料目录和可丢弃的测试应用副本，验证旧版退出、原位完整替换、新版启动及健康或符合规格的人工处理结果。首次补装也沿用实际安装包版本、运行窗口和更新界面的验证方式，不以源码中的入口代替已安装应用的证据。先完成无 Developer ID 的实机实验，再允许正式安装功能进入交付。
3. **既有数据保护边界。** 复用退出保存、完整加密备份及恢复测试的真实存储与临时目录，验证未保存编辑落盘、附件保留、备份可恢复、无主密码或备份失败阻止安装。只检查公开行为和数据结果，不断言私有方法调用次数。

位置预检复用现有安装协调器边界，以实际安装目标规则和隔离临时目录覆盖拒绝路径。观察安装请求失败后的副作用：无新完整备份、无已启动助手、无退出、未进入写入冻结且本地工作仍可继续；注入的保存、备份及启动依赖只用于观察这些外部行为，不把内部实现步骤或私有调用次数固化为契约。真实磁盘映像和系统授权仍在 macOS 实机边界验证。

错误呈现沿用已有 Electron 安装版回归，从主进程错误经过真实 IPC 到更新界面，检查可见消息和操作可用性。仅替换安装返回错误的界面用例只证明消息呈现，不能据此声称真实预检、完整备份或系统授权已验收。安装版健康回执、损坏更新历史仍能启动工作台、备份失败保持可用等既有用例为本轮先例。

本轮界面验收沿用现有更新与外观桌面回归：通过已存在的快照和主进程到窗口的状态订阅，在隔离资料目录中构造状态，再用用户可见的入口、说明、进度及动作验证结果；不为界面场景实际下载虚构版本或改写真实用户的更新状态。现有安装版启动入口继续用于打包应用验证，设置与外观回归中的主题、可访问性和焦点检查作为先例。

关闭问题额外要求在真实 macOS 安装窗口中使用鼠标指针点击。浏览器自动化输入可能绕过原生窗口拖拽命中，辅助功能触发也可能直接调用按钮动作，二者通过均不足以单独确认本问题修复。回归需覆盖关闭按钮与底层工具栏重叠的布局，验证鼠标关闭、再次打开、Esc 关闭及焦点返回；平台拖拽排除状态仅作为辅助断言，最终以真实指针结果确认。测试关注这些外部行为，不固定内部函数调用次数或装饰性类名。

必要场景包括：

- 正常正式版本升级、无更新、预发布过滤、版本不合法、无 Release、缺少 arm64 资产。
- 离线、限流、下载中断、哈希不匹配、大小超限、异常重定向、恶意压缩包、错误应用身份。
- 下载校验完成后主动弹窗；长说明、深浅主题、窄窗口和可访问性偏好不遮挡重启操作。稍后、关闭、Esc、焦点返回、再次打开、重复状态不再提醒及安装错误提示均通过现有桌面接口验证。
- 真实 macOS 助手健康成功后删除旧应用与本次 ZIP／解压目录，保留资料、备份和日志；替换失败、中断和健康未确认不执行成功清理。未知或符号链接目录应保留并记录清理未完成，历史与定位入口与实际结果一致。
- 开发模式拒绝安装，重复点击或多实例不并发安装。
- 保存失败、备份失败、恢复或轮换主密码进行中均不退出并替换。
- 工具任务仍在后台运行时拒绝准备安装；任务完成后可重试，准备期间新工具任务不能绕过写入冻结。
- 真实可写安装位置成功；DMG/只读位置、权限拒绝、安全拦截具有可理解结果。
- 原应用位于可写的“应用程序”，当前进程却运行在 App Translocation 时，准确拒绝安装并提供 Finder 指引，不误报为正在运行磁盘映像。
- 无效应用目录、符号链接、所有权不符、父目录不可写均在保存、冻结和新建完整备份前失败；重复点击无效目标不能产生新的备份或助手。
- 早期预检后目标条件发生变化时，安装助手启动前的复核仍能拒绝操作，应用保持可恢复状态；已经完成的完整备份保留。
- 原生 IPC 错误含有或不含外层错误前缀时，界面均保留可操作的中文原因，不显示远程方法调用包装。
- 替换各阶段失败与进程中断能够保留或恢复旧应用，恢复失败时材料仍可定位。
- 新版实际版本匹配，窗口与 IPC 可用；数据库或页面加载失败不记录成功。
- schema 未改变和发生迁移两种场景，证明不会静默恢复旧数据库或丢失更新后的数据。
- 真实 GitHub 下载途径和 macOS 安全属性必须纳入发布验收；仅本地产生的包测试通过，不能证明公网下载包也可启动。
- 在真实 Electron 运行时解压真实发布结构的应用包，验证 ASAR 文件和框架链接；仅在 Node.js 中执行解压测试不足以覆盖该行为。
- 暂存复制保留 quarantine，丢失属性的更新即使成功启动也必须判为验收失败；不得为得到绿色结果而移除属性或关闭系统保护。
- 新版停在应用代码初始化之前时，独立助手按时记录人工处理并保留可读恢复材料；验证备份能在隔离资料目录恢复文档和实际显示的图片。
- 私有仓库的实际 Git 读取授权、资产 API 和 CDN 跳转分别验证；无凭据时显示明确指导，不泄露授权、不误报已是最新。
- 首次从没有更新器的旧安装包补装后，实际运行版本、更新入口及检查结果可见；已有资料保持，旧应用副本仍可定位。本机缓存包复用必须先匹配已发布资产内容。
- 源码合并与实际安装版本分别核对；没有更高正式版本时在设置中仍可见检查入口，品牌旁不显示更新按钮，不能用开发模式、静态源码或同名安装包替代实际安装验证。
- 使用既有状态订阅验证手动检查只在设置中、按钮位于品牌副标题右侧、发现新版才显示、无目标版本的检查失败不显示、下载与待安装时保留，并覆盖弹窗关闭和小窗口深浅主题。
- 有目标版本的下载失败保留入口和重试下载；无目标版本的检查失败隐藏品牌按钮，但在设置中保留可理解的原因与可用的重试检查。
- 长说明、小窗口及与工具栏拖拽区域重叠时，关闭按钮实际可点击；Esc 可关闭，重复打开正常，焦点返回有效入口，关闭面板不使正在下载的任务消失。
- 主题切换、减少动态效果、进度可访问名称、字节与百分比、默认折叠的来源和历史均沿用现有设置与更新测试边界。共享对话框改动后复核既有外观与台账交互。
- 真实 macOS 拦截时，记录实际系统提示和单个应用授权步骤；没有看到身份验证窗口时保持“尚未确认”的结论，不以后台进程或点击回执代替观察。
- 人工恢复后核对实际进程位于正常安装位置、版本与正式资产一致、主窗口可用、原资料代次和已有设置保持、更新检查正常；原超时记录仍然保留。
- 真实用户资料不作为可清理的测试夹具。自动化使用隔离资料目录；用户明确要求的本机安装只做与安装相关的保留和只读核对，不执行额外的真实资料恢复演练。

### 验收结果的含义

| 结果 | 必要证据 | 可作出的结论 |
| --- | --- | --- |
| 更新成功 | 目标位置的完整新版包、安全属性保持、版本与资料库及窗口和 IPC 健康回执 | 本次更新成功；如果使用测试网络响应，不能同时宣称公网下载已验收 |
| 需要人工处理 | 有限时的明确原因、旧包与加密备份保留、可读恢复说明和日志 | 对应的系统拦截或失败处理路径通过；不能宣称新版健康启动成功 |
| 首次补装完成 | 安装包来源与校验明确，旧应用正常退出，新进程版本、资料可用和更新界面得到确认 | 本机已启用更新器；不能代替带隔离属性的真实版本对自动升级健康验收 |
| 人工恢复启动完成 | 正式资产校验、原资料与旧应用保留、系统所需的单个应用授权完成、正常安装位置的实际窗口和版本及检查结果 | 当前安装版可使用；保留原事务的失败或人工处理结果，不宣称无人值守升级成功 |
| 验收未完成 | 缺少实际已发布版本对、真实下载或明确结果证据 | 明确列出未验证项，不能以本地测试替代；人工处理结果按对应行单独解释 |

正式网络升级验收应使用固定仓库中实际已发布的旧版和新版 Release，走真实资产下载、保存备份、原位置替换和结果确认。私有仓库使用本机已有的读取授权，并分别记录私有授权及匿名公开下载结果。本机人工处理路径通过不代替真实网络验收，也不等于已证明健康的无人值守升级。

## Out of Scope

- 更新 sub2api 服务、执行 git pull、管理部署命令或修改用户源码目录。
- Windows、Intel Mac、Linux 首版自动安装；Beta 通道、任意仓库更新源配置、内置共享令牌或改变源码仓库可见性。
- Apple Developer ID、Apple 公证和系统安全策略绕过。
- 无需任何系统交互的跨所有 macOS 环境安装保证。
- 新版本彻底无法启动后的全自动健康回滚、自动数据库降级和自动覆盖数据备份恢复。
- 差分更新、跨设备同步、应用退出后的后台版本轮询。
- 在无更新器旧版中远程注入更新能力，或通过合并主分支自动替换用户设备上的应用。
- 将关闭查看面板解释为取消下载、关闭工作台或撤销已经开始的安装事务。
- 在本轮界面整理中增加生产测试接口、修改更新源授权或资料库结构。
- 自动操作用户的 Touch ID、收集或保存 macOS 管理员密码、关闭全局安全检查、移除下载隔离属性或修改安装目录所有权。
- 猜测 App Translocation 对应的原目录并静默替换另一应用，或以直接运行内部可执行文件代替正常系统打开流程。
- 因人工恢复成功而删除旧失败记录、补写成功健康回执或承诺未来每个版本都能无人值守启动。
- 重写旧提交署名、强制覆盖共享历史、覆盖既有 Release 资产，或未经明确要求触发新版本发布。源码提交、正式发布和本机安装分别执行和记录；维护者双击发布脚本继续使用独立规格。
