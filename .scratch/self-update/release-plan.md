## v0.1.2：版本升级验收目标

本版本保持相同功能，用于验证 v0.1.1 至 v0.1.2 的真实版本升级。仅提高应用版本号，不将本地实验结果表述为真实发布升级成功。

tag 应指向本次将 `package.json` 及 lockfile 提升到 0.1.2 的版本准备提交，不能将两个 tag 指向同一个应用版本提交。

拟用发布说明：

> 维护版本，用于验证首个更新器版本至下一正式版本的升级路径。保留资料保存、完整加密备份、下载校验、原位置替换和启动健康确认。无 Developer ID 签名及公证；macOS 可能要求人工允许启动，应用会明确显示处理结果。

1. 依次推送匹配各自应用版本提交的 v0.1.1、v0.1.2 tag，执行已有发布工作流；每个版本均通过构建验证、上传完整资产后才发布。

3. 在隔离资料目录启动该基线，经真实 GitHub API 和资产下载升级至 v0.1.2，验证备份、替换、安全属性和健康或人工处理结果。
4. 更新任务 07 的验收记录。健康启动、人工处理、私有授权与匿名公开下载分别记录。

发布需维护者确认的依据：`docs/releases.md` 要求“只有维护者明确准备公开时才推送版本 tag”；任务 06 也记录“未获额外授权不发布真实公开版本”。本次保持私有仓库，发布仅影响该仓库有权限的读者，仍不提前推送 tag。
