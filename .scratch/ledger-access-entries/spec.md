# 系统访问入口与服务器台账：补充需求规格

Status: ready-for-agent

2026-10-18：用户通过 grill-with-docs 提出补充需求，Q1–Q10 已答复，并通过 Q11 确认全文及默认操作规则，授权纳入既定 goal 继续实现。

## 目标与已确认范围

在一个系统内快速找到 Jenkins、GitLab 等工具的登录地址与账号，以及多台服务器的名称、IP、用途和可选账号。延续个人本地使用、轻量录入、秘密加密、按需解锁和完整备份迁移。

访问入口与服务器均属于单个系统，可以是系统通用，也可以指定该系统的一个环境。系统切换当前项目不改变这些记录的身份或内容。跨系统使用时建立独立副本，不建立共享关系。

### 访问入口

- 一个入口代表一套外部应用或工具，例如 Jenkins、GitLab、Gitea。
- 一个入口有多个具名地址，例如“内网”“外网”；账号属于整个入口，不逐个绑定地址。生产 Jenkins 与测试 Jenkins 若是独立部署、账号体系不同，分别建立入口。
- 支持多个账号，可按用途或角色区分。账号继续使用既有密码、Token、私钥保护能力；普通地址和账号元数据在锁定时仍可查询。
- Git 在此指网页登录平台。服务的仓库 clone／SSH 地址继续在既有服务仓库信息中维护。
- 系统详情提供访问入口区域和环境筛选；支持全局搜索、固定到工作台、在外部浏览器打开地址、复制用户名及按需解锁复制秘密。
- 可设置常用地址和常用账号，初始使用第一项。首页默认操作使用常用项，也能展开切换；复制时清晰显示账号用途与用户名。

### 服务器

- 一个系统支持多台服务器。基本信息包括名称、IP、操作系统、CPU、内存、硬盘、用途，保留既有端口和备注；这些字段直接提供录入，不要求先添加自定义字段。CPU 允许型号与核数自由描述，内存与硬盘允许“32G”“500G”等文本。除名称外均可留空。
- 无账号权限时只登记机器资料。有权限时可以登记一个或多个账号，密码按既有机制加密。
- 支持系统通用或指定环境，不强迫先创建环境。
- 本轮只做服务器清单与用途说明，不增加服务和服务器的显式部署关联或拓扑。
- 复用并扩展现有服务器资源，不另造一套相同机器记录。已有服务器、多角色账号、秘密和资料引用在升级后保留。

### 快速录入

访问入口使用小弹层：名称必填，地址、用户名、密码同屏选填；填写首个账号时自动使用“默认账号”作为用途，可修改或增加其他角色。不要求先创建入口，再跳到另一页面录账号。

服务器同样沿用轻量录入原则：名称即可建立，IP、用途、环境及账号均可随后补充。查询机器不要求持有或填写登录凭据。

服务器新增弹层支持展开录入操作系统、CPU、内存和硬盘；详情中这些基本信息直接可编辑，并随复制、搜索和完整备份保留。该项由用户在确认实现后提供截图追加，已明确授权实现。

## 已整体确认的操作规则

以下操作规则已在 Q11 随全文整体确认：

1. 默认展示系统全部入口或服务器，明确标注“通用”或环境；筛选某环境时展示该环境及系统通用记录，并允许只看通用记录。
2. 地址可先不填写。新增首个地址默认标记“主地址”，可改名、排序；HTTP(S) 地址可打开，复制不携带账号或密码。应用不做自动登录、网页密码填充或可用性探测。
3. 删除常用地址或账号后，有剩余项则使用排序第一项；没有地址时不显示可执行的打开操作，没有账号时可随时添加。操作前始终能看清当前目标。
4. 新增表单仅填写用户名或秘密时才建立首个账号；仅记地址不生成空账号。秘密保存取消或失败时保留输入、明确保存状态并允许重试，不假报完整成功。
5. 复制入口或服务器时可选择目标系统及其环境；默认复制普通资料、地址与账号元数据，秘密只有明确勾选并解锁后才复制。副本独立维护，取消解锁不创建含秘密的半成品副本。
6. 删除入口及其账号前展示影响并确认；删除单个地址不删除账号。服务器沿用既有引用保护，不自动连带删除任务、文档。删除或调整关联后清理失效收藏与常用项。
7. 搜索覆盖入口名称、地址标签、地址、账号用途和用户名，以及服务器名称、IP、用途；秘密不参与搜索。结果展示系统和通用／环境标识。服务器账号仍可使用既有首页收藏能力。
8. 入口可以有普通备注；本轮不新增独立的“入口任务／入口文档”关联类型，相关任务与文档继续按系统／环境记录。已有服务器资料引用保持有效。
9. 完整备份包含新记录、地址顺序、常用项、收藏和秘密；旧版应用资料升级及旧备份恢复不能丢失原有资源、账号、秘密、图片或关联。新资料格式继续执行严格版本与结构检查。

## 验收场景

1. **无环境先录入**：在未创建环境的系统中，仅填写名称创建 Jenkins 入口及服务器；重启后仍存在。
2. **多地址、多账号**：同一 Jenkins 记录内外网地址以及管理员、只读账号；切换常用项、打开地址、复制指定账号，重启后顺序和选择保留。
3. **独立部署**：为生产、测试分别建立 Jenkins 入口；搜索及环境筛选能区分，不误复制另一入口的密码。
4. **服务器无凭据**：记录多台机器的名称、IP 和用途而不填账号；日后补入多组账号，普通查询始终不要求解锁。
5. **快速录入与失败**：名称、地址和首个账号可一次录入；主密码设置／解锁取消或秘密保存失败时不清空输入、不误报成功，重试不会重复创建。
6. **首页与搜索**：固定 Jenkins 到首页，从全局搜索定位 GitLab；打开常用地址、切换其他地址、复制账号和秘密，显示清楚当前目标。
7. **环境与独立副本**：通用记录在所选环境中可见；复制到另一个系统后修改副本不影响原记录；复制秘密需要显式选择及解锁。
8. **常用项与删除**：删除常用地址或账号后的替代规则明确；删地址不丢账号；服务器被资料引用时沿用既有保护。
9. **升级与完整恢复**：已有服务器、账号及引用升级后不变；新增通用记录、多地址、用途、常用项和秘密可完整备份、恢复及继续编辑；旧备份仍可恢复。
10. **长期系统**：系统切换当前项目或旧项目归档后，新台账继续可用，不改写历史任务和文档。

## 现有能力与实现约束

只读核查确认：现有系统只有一个 URL，资源只有一个主地址；资源和账号都强制属于环境。“其他资源”可保存登录地址及多个加密账号，但尚不能满足系统直属、多地址及首页直接打开入口的需求。服务器已支持多账号与加密秘密，用途目前通过附加字段存储。

实现应统一复用现有服务器和账号能力，补充系统直属归属及访问入口模型；同步更新资料迁移、上下文解析、全局搜索、收藏、完整备份与恢复校验。Redis 和其他既有资源不因本轮需求自动改变归属规则。秘密继续走原加密机制，不另建明文密码存储或重复密码库。
