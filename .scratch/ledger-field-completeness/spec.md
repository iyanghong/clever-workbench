# 台账字段与新增录入完善

Status: ready-for-human

2026-10-22。用户指出数据库／中间件与应用部署新增时能录入的信息过少，要求检查整个台账模块，补充有用字段，并强调新增字段应可选。用户指定 grill-with-docs，按 grilling 与 domain-modeling 分轮讨论、记录术语和决策；用户已通过 Q11 确认方案并明确授权开始实现。实现与验证已完成，见[实施记录](implementation.md)。

## 已确认的原则

- 范围是整个台账模块，包括访问入口、账号、服务器、数据库／中间件、应用部署、运行维护，以及相关的系统、环境和文档入口。
- 常用信息直接展示，配置和运维信息分组折叠；新增时可以选填，详情继续可编辑。除名称及维持归属关系所必需的背景外，新增业务字段均可留空。
- 数据库／中间件支持多组具名连接，每组可记录地址、端口、用途或节点角色，可选关联已有服务器。
- 保留一项应用／服务在多个环境下部署到多个节点的关系，补充可选的部署方式、版本、路径、启停命令、日志位置、健康检查地址。这些信息仅用于记录，不执行命令。
- 数据库／中间件按产品展示可选字段模板，产品可选常用项也可手填，保留普通附加字段；不适用的字段不同时摊开。
- 新增应用时可同时填写首个部署节点，整组可跳过；填写具体节点时须有节点名称和环境，服务器及其他资料可后补。
- 作业补充脚本或命令、执行用户、日志位置和步骤文档；备份补充方式、目标位置、保留周期、恢复说明、最近恢复验证时间与结果。类型、频率、状态和关联对象在新增时即可填写。
- 复用现有技术文档，应用或部署节点可引用多份本系统文档或通用文档；一份正文可多处引用，移除引用不删除文档，并从对应详情打开。
- 资源的首组连接默认为常用，可手动改选；未填独立地址时显示所关联服务器的地址并注明来源，手填地址优先。账号仍属于资源，服务器登录账号与数据库账号分开。
- 访问入口新增可填具名地址、账号角色和说明；独立账号新增可填用户名、密码、Token、私钥及说明；服务器补登录协议、位置、资产编号及说明；系统新增可填登录地址和说明，环境可填说明。多账号、多地址按需添加，新增字段均可留空，不引入采购或人员管理。
- 服务公共资料与各环境的部署资料分开，避免生产、测试版本或路径互相覆盖。沿用既有系统身份、多范围展示、独立账号与秘密加密边界。

## 已确认的操作规则

这些规则将 Q1～Q10 落到可交付的操作行为，不再增加独立的功能模块。

### 录入和可选性

名称和必要归属沿用现有规则：资源、入口、应用及运维需要所属系统；独立账号需要资源、入口或环境；具体部署节点需要服务、环境和节点名称。已从当前页面确认的背景自动带入，不要求用户重复填写。应用的“同时记录部署”整组可跳过，普通资料不因未建服务器或没有凭据而无法保存。

资源连接可以逐组添加、排序、删除，名称未填时使用可辨认的默认名称；整行空白不创建连接，但只填端口等部分已知资料仍允许保存。常用连接被删除时取剩余首组，没有连接则显示未填写。只继承关联服务器的地址，不把服务器登录端口当作数据库端口。解除服务器关联时保留当前显示的地址作为独立地址，避免资料消失。

切换产品模板或作业／备份类型，不静默删除已录入的普通字段；暂时不适用的信息可在附加信息中查看、修改或显式删除。没有预设模板的产品仍可按通用字段及附加字段记录。大型内容继续使用操作文档；命令、频率、路径和恢复验证结果都只是用户记录，不产生执行或监控任务。

新增表单采用一次提交；关闭或离开有内容的表单时提醒保留或明确放弃，提交失败保留输入。详情沿用现有自动保存和秘密的专用保存边界。已有服务节点、账号及范围切换不被新表单重建或覆盖。

### 文档引用和导出

应用和部署节点可引用本系统或通用文档，不引用其他系统专属文档；同一对象不重复添加同一引用。原有文档归属保持原义，引用不是移动或复制正文。运维步骤仍沿用现有单份本系统文档的关系，本轮不顺带改为多文档关系。

系统资料导出勾选包含文档时，包含原有本系统文档，以及该系统应用／节点直接引用的通用文档；同一正文只导出一次，并在对应对象处保留文档名称与跳转关系。未引用的通用文档、其他系统资料不进入包中。取消包含文档时不带正文，仍保持现有单文件／ZIP 选择规则与秘密授权边界。

文档仍有引用时，删除或改归属若会破坏引用，提示引用位置并要求先解除或调整；不静默删除共享正文，也不留下失效关联。删除应用或节点只移除其自己的文档引用，保留正文及其他对象的引用；其他已有业务引用保护继续生效。

### 复制、批量与兼容

同系统复制资源可保留合法服务器关联；跨系统复制仍是独立记录，复制全部具名连接及其当前显示地址，解除原系统服务器关联，不自动复制或猜测目标服务器。连接、账号等副本获得独立身份；秘密仍由用户明确选择复制。原有资源复制不因本次字段完善自动复制文档正文或其他对象。

批量录入继续一行一个对象，补齐对应的普通模板字段；资源行可录首组连接与首个账号，更多连接和账号在详情按需添加。部署节点可单独批量录入，不在一个应用单元格内隐式创建多节点；不增加文件导入、混合类型或批量覆盖旧记录。普通字段格式、名称及端口等校验与单条录入一致。

旧资料保留对象、账号、文档与秘密身份。数据库／中间件原地址和端口转为默认连接，只有端口的旧资料也必须保留；空连接资料不被当成不存在的有效地址。迁移重复运行不重复生成记录。旧字段与新连接只保留一个权威值，修改名称、范围等旧调用不会清空新字段或连接。普通资料和新关系纳入搜索、复制、导出及完整备份恢复，旧备份按兼容迁移继续恢复。

## 必须覆盖的实施边界

以下是达成已确认需求所需的完整性要求，不另行扩展产品功能。

- 单条新增、详情编辑和现有批量录入使用一致的字段含义。批量沿用每行一个对象、可带首个账号的边界，不通过一个单元格的换行自动拆出连接、节点或账号。
- 名称与必要归属以外的字段可空；填写后仍校验端口、日期、长度、枚举和引用所属系统。数据库引擎未知不阻止录入，自定义普通字段不能冒充加密秘密。
- 一次提交的主体、连接、首个账号和秘密，或应用与可选首个节点，应作为一次业务变更整体保存。失败保留输入、允许重试，不留下半条记录。
- 普通资料、连接串及命令文本不自动加密；密码、Token、私钥必须沿用专用秘密字段。未确认提交的含秘密草稿不落普通本地存储。
- 固定／按需描述运行安排；普通进程、Docker、Kubernetes 描述部署方式，不能用新选项覆盖旧 `fixed/scheduled` 字段的含义。配置路径、日志位置等不伪装成本地可执行路径。
- 新连接使用稳定身份。旧资源的 `address/port` 升级为保留原值的默认连接，不重建资源或账号；缺省更新不能清空已有连接。服务器原有主地址行为保持兼容。
- 主进程检查所有服务器、服务、环境、文档关联；删除仍被引用的对象时保护引用，不能静默删除其他台账或正文。
- 多连接及新资料纳入列表／详情展示、全局搜索、账号摘要、台账复制、系统资料包、完整备份及恢复验证。秘密不进入普通快照或搜索。
- 持久化关系变动需同步版本、迁移、恢复验证和旧备份兼容；较旧版本应明确拒绝更高版本资料，不降级数据库。

重点检查入口：`LedgerCaptureForm`、`QuickRecord`、`WorkspaceEditors`、`Resources`、`Accounts`、`PasteLedger`、`LedgerWorkspace`；共享契约、preload 与 `secureHandler`；`ledger`、`ledger-workspace`、`documents`、`vault`；搜索、复制、系统导出及备份恢复。

## 验收场景草案

1. 从分类入口和全局新建录入同一类对象，字段含义一致；仅填名称及必要归属可保存，普通高级字段留空不拦截。
2. 数据库可一次记录连接和账号；多个连接及可选服务器关联可保存、重启后继续编辑，普通字段不含明文秘密。
3. 应用只填公共信息可保存；同时填写首个节点时校验环境并原子保存，同一应用不同环境的版本、路径和命令互不覆盖。
4. 作业与备份按类型显示可选字段，切换类型不静默丢弃已填资料；验证信息只是记录，不被标记为本工具自动执行结果。
5. 新增、编辑、关闭、切页、退出、导出与更新时遵守现有保存协调；未提交录入保留或由用户明确放弃，失败后可修正重试。
6. 字段和关系经搜索、复制、资料导出与完整备份恢复后保留；旧资源、旧节点、旧账号和旧备份仍能使用；验证删除和跨系统复制的引用边界。
7. 深浅主题、跟随系统、辅助外观、正常和窄窗口、键盘 Tab／Esc、焦点返回及长内容滚动可用；验收区分开发构建、安装包与目标平台实机。
