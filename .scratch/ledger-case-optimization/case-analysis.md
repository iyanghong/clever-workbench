## 案例反映的资料结构

| 资料 | 实际结构 | 对功能的启示 |
| --- | --- | --- |
| 常用地址 | 3 组、19 行，分组混合环境、网络域和办公地点；后两组各 7 行内容逐格相同 | 明确分组含义；同一对象可以多处展示，但不能仅凭地址或账号相同自动合并 |
| 设备清单 | 生产、测试、仿真共 24 项，其中 23 项常规服务器、1 项密码机；运维终端另有 5 行 | 服务器字段已有基础；型号、资产编号、存放位置等可按类型选填，不宜强迫所有设备填写同一大表 |
| 访问与接入 | 工具入口、负载均衡入口、服务器直达入口，以及验证码获取说明 | 继续使用多地址、多账号；访问条件与操作说明应能就近查看 |
| 数据库 | 版本、实例名、业务库、主备节点、字符集、页大小、目录、配置及日志位置、备份策略 | 提供数据库常用字段模板，并区分机器登录账号、数据库身份和库名；资料没有给出连接串或多角色数据库账号表 |
| 应用与组件 | 应用 11 行、组件 5 种、部署规格 4 行，包含固定多节点和 8 节点按需部署 | 现有每个服务／环境只有一条地址，无法清楚表达多节点部署；节点号尚不能直接映射成服务器记录 |
| 网络访问 | 23 行访问关系，含源／目的名称、IP 组、端口、协议和用途 | 可讨论结构化访问清单；其必要性不同于服务器清单，不应默认扩成网络资产管理 |
| 周期运行规则 | 59 行规则，部分行包含多个任务名；有轮询、每日及周／月／年频率 | 这是系统运行作业，与个人工作任务不同；59 行不等于 59 个独立作业 |
| 状态及过程说明 | 备份已失效、服务弃用及迁往其他位置；另有备份类型与文字描述不一致 | 保留状态、说明和待确认信息，避免只记一份看似可用的地址／策略 |

数据库、直达入口和网络矩阵会重复引用设备地址。同一个 host 也可以对应不同路径或端口的入口；IP、URL 和用户名均不能独立充当对象身份。原文中的重复内容可能来自共同访问同一对象、共用部署或文档复制遗留，需要维护者确认。

拓扑图片呈现网络域、安全区和组织边界，以及业务服务器、终端、VPN、交换平台、防火墙和 IPS 的连通路径。图没有方向箭头，不能据此推断调用方向；图标数量也不能累加成新的设备库存。结构化网络方向如需录入，应以明确的源／目的矩阵和维护者确认为准。

源资料未提供应用部署目录、应用日志目录或实际启停命令，不能把数据库和备份路径误认为应用路径。文档内容也不证明目前仍在使用；存在矛盾的记录应保留疑点。

### 粘贴结构补充

两份资料共 21 张表：16 张为带表头的逐行清单，5 张为两列键值资料卡，后者包括接入、系统访问、两套数据库及组件信息。数据库资料卡应整表映射为一份资源，不能把每个字段新增为对象；组件表则可按逐行组件清单理解，因此不能只凭两列结构自动决定对象数量。

运维终端有纵向合并地点，设备清单有一行横向合并的特殊设备资料；网络矩阵单格中可有多行地址或端口，部分作业名称以顿号并列。粘贴预览需要保留结构、提供校对，不将空格、换行或标点当作确定的对象身份或拆分依据。

## 当前功能与实际缺口

| 当前能力 | 本轮可讨论的改进 |
| --- | --- |
| 系统独立于项目、环境、系统通用入口／服务器 | 分清部署环境与地点／网络，决定是否需要可选标签或多范围展示 |
| 多地址入口、多角色账号、常用地址／账号、全局搜索和首页常用 | 改善密集资料的快速查找、复制和输入体验，不重复建设已有功能 |
| 服务器名称、IP、用途、操作系统、CPU、内存、硬盘及附加字段 | 按类型提供常用字段模板，补充资料中确实常用的资产字段 |
| Redis、服务器、其他资源；普通附加字段 | 数据库等常用资源的快捷模板，减少每次手工创建字段 |
| 服务公共信息和服务×环境的一条部署记录 | 可选地关联多台服务器、表达固定与按需部署；不强制先建齐关系 |
| 系统文档、通用文档、环境／资源背景 | 用文档承载操作过程和复杂说明；是否另建作业／备份清单待确认 |
| 系统完整可读导出及加密备份 | 新资料和关系经确认后统一纳入；保留两种用途的既有边界 |

## 工作任务调整的完整范围

用户已明确任务只保留可选系统关联。现有实现不止有项目控件，还保存项目、系统、环境和资源，并让项目决定任务的可见性、回顾和归档行为。

| 范围 | 需要一致调整的行为 |
| --- | --- |
| 新建、快录、详情、草稿 | 系统为唯一可选绑定，不再从系统当前项目或页面项目继承任务项目；从台账进入时只带所属系统 |
| 任务列表、首页、搜索 | 使用系统名称与系统范围；项目归档不再隐藏或限制任务 |
| 工作回顾 | 保持原有开始到实际完成的口径，项目维度改为系统；保留月度入口 |
| 完成、重开、回收站 | 任务操作不再要求恢复其旧项目 |
| 项目管理与归档 | 项目继续记录系统阶段历史；项目管理入口从任务页移到台账，移除项目任务数及未完成任务拦截 |
| 资源引用 | 任务不再产生新的环境／资源绑定；文档自身的细粒度关联保持独立 |
| 导出、备份、升级 | 旧任务与草稿按同一迁移规则处理，不因旧项目状态丢失或隐藏；历史关联如何保留待用户选择 |

已有任务可能只有项目而没有系统，系统与项目的历史关联并非一对一，不能自动反推所属系统。用户已通过 Q6 确认：保留已有系统，缺失者先归入未关联系统；旧关联仅保留为历史说明。

实现触点依据：`src/features/tasks/TaskWorkspace.tsx`、`QuickTask.tsx`、`src/components/Detail.tsx`、`Timeline.tsx`、`src/features/home/HomePage.tsx`、`src/features/ledger/RelatedWork.tsx`、`electron/store.ts`、`ledger.ts`、`search.ts`、`system-export.ts`、`backup.ts`。这些是静态代码核查，本轮没有运行应用或改业务代码。

## 首轮选择已确认

1. 部署环境保留，地点／网络使用可选标签。
2. 同一对象经确认后复用，在多个范围展示。
3. 增加可选多机部署关联，网络访问矩阵仍用文档承载。
4. 运行作业、备份采用轻量运维清单加文档。
5. 支持表格粘贴、映射与预览后的批量录入。
6. 旧任务保留历史，不自动猜测系统。

以上为用户已确认的选择。依赖这些选择的字段、页面、批量录入校对及兼容细节，继续按[需求草案](spec.md)讨论；业务代码尚未修改。
