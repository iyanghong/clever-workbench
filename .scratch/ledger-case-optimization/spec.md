# 基于实际资料优化系统台账与任务归属

Status: ready-for-human

## 已明确的需求

- 工作任务可关联一个系统，也可以不关联；不再直接绑定项目。
- 任务的新建、编辑和上下文继承收敛为系统选择；现有环境／资源绑定也退出新任务录入。旧任务的项目等关联保留为历史说明，不继续参与绑定或业务规则。
- 系统身份与当前／历史项目的既有关系不因上述要求自动删除。用户只明确调整了工作任务。
- 结合实际资料审视对象组织、查询与复制、录入维护和导出，避免增加不必要的录入步骤。
- 原始案例只读使用；分析记录使用结构和虚构例子，不复制真实地址、账号或秘密。

## 已记录的默认操作规则

以下规则将已确认方向落实为可验收的行为，Q11 选择先保留文档。界面基本结构已通过 Q12–Q14 确认，具体排列和密度继续核对；未实施业务代码。

### 入口与快速录入

全局继续保留工作台、台账、任务、文档和工作回顾。台账顶部提供可搜索的系统切换器，常用分类平铺为访问入口、账号、服务器、数据库／中间件、应用部署、运行维护和文档；环境及标签统一作为筛选。账号页汇总原有账号并标明所属对象，不新建账号副本；系统列表不再常驻占用第二列。常用对象和个人待办继续由全局工作台承接，台账直接恢复上次的查询清单。

默认使用清单展示可查询字段，点击条目打开只读详情，账号和复制操作优先呈现；需要修改时点击编辑，普通字段自动保存，秘密仍明确保存。字段较多的配置按需展开；宽窗口清单与详情并排，窄窗口覆盖显示详情并保留清单状态。新建沿用当前系统与环境，名称以外均可选填；标签可直接输入或选择已有值。

项目管理迁到台账的项目档案入口；系统当前／历史项目和文档原有项目背景保留，任务页不再承担项目管理。

### 环境、标签与同一对象

访问入口和资源直接属于一个系统，适用范围可选系统通用或指定一个／多个环境。查看某个环境时显示该环境适用及系统通用条目；标签用于地点、网络域等特征，可与环境共同筛选。入口、资源、服务和运维条目均可带标签，标签不是新的归属或必填目录。

标签在当前系统内管理，同名标签不使不同系统共享台账。服务公共资料仍只记录一次，各环境的部署信息独立；运行维护和文档保留明确的可选环境背景，不因多处展示自动复制。

复用只发生于已经确认是同一对象的记录。地址、备注、账号和秘密均随该对象一处修改、多处生效；沿用此前已确认的“账号属于整个入口或资源”规则，环境特有且独立的部署／账号体系分别建立条目，不新增隐形的环境覆盖密码。跨系统继续复制为独立对象，复制秘密仍需明确选择和解锁。

全局搜索显示系统、适用环境和标签，覆盖新增资源字段、部署节点与运维资料，秘密仍不参与搜索。首页已有常用入口和账号继续通过对象身份定位；从具体环境进入时保留该范围，跨环境对象不任意选取一个环境来冒充其唯一归属，常用地址／账号的现有选择保持有效。

从某环境移除展示范围只改变范围，不删除对象或账号。删除整个对象时明确影响全部范围、账号和秘密；有文档、部署或运维引用时先解除或转移引用，不静默删除相关资料。改变范围不自动改写已有文档等历史背景。删除环境前必须处理其仍被使用的范围及关联，不把最后一个范围静默改成系统通用；删除标签只移除标记。

### 资源与账号

服务器沿用已有名称、IP、用途、操作系统、CPU、内存、硬盘、端口和多账号能力。型号、资产编号、存放位置等以常用模板或附加字段补充，不要求每台机器填写。

数据库提供类型、版本、实例名、库名、主备信息，以及目录／配置／日志等常用模板字段，均可留空；库名可记录多个，不新增强制的实例到库到账号层级。数据库账号归属于该数据库资源，用途可注明访问的库；服务器登录账号和数据库账号仍分开。缓存／中间件及其他资源继续可用，普通附加字段保留。

资源、入口和所属账号保持稳定身份。环境直属的系统角色账号继续可用；对象跨范围展示时不重复创建账号，不因某个展示范围消失而清除密码。普通字段和文档仍不自动识别、加密自由文本中的秘密，账号凭据使用既有加密入口。

### 应用与部署

服务的名称、仓库等公共信息与环境部署分开。每个服务在同一环境下可维护多条部署节点，节点各有名称、地址、端口、备注及可选服务器关联；可以多条节点关联同一服务器，不根据 IP 自动合并。

固定部署可逐台关联本系统服务器，机器未建齐时先用节点名称记录。按需部署可先记录节点规模与说明，不为一个“8 节点”描述虚构 8 台服务器。节点独立地址留空时可展示关联服务器的地址并标明来源；手工填写的地址作为该节点的独立信息，不被服务器更新覆盖。

只允许关联本系统服务器。服务器当前适用范围与部署环境不同可提示补充范围，不自动搬移或复制机器，也不妨碍先记录已知部署事实。删除服务器前保留引用保护，可明确解除服务器关联并保留节点名称、独立地址和说明。

服务可记录在用、停用、待确认状态及原因；停用不删除已有部署与文档。网络访问矩阵和拓扑使用系统 Markdown 文档及图片承载，不建立网络设备库存或结构化网络关系编辑器。

### 运行维护

系统内分别记录运行作业和备份策略，名称即可建立，频率自由文本，状态在用、停用、待确认。可选一个环境和一个本系统服务或资源，详细步骤可关联本系统技术文档。未关联对象时仍可保存，清单能按类型、环境、标签和状态查找。

频率用于记录与查询，作业或备份仍由原系统／调度器执行。失效和弃用通过状态与说明明确表达，来源矛盾保留待确认，不把失效说明变成个人任务的已完成状态。个人需要处理的排障或恢复工作仍另记工作任务。

数据库详情可查看其相关备份策略，策略在运维清单维护。资料卡中尚未整理的备份文字可先原样放在数据库说明，再由用户整理成策略；不根据一段描述自动拆出多个对象或维护两套相互独立的策略。

### 表格粘贴与校对

先选系统、条目类型及本次范围，粘贴后映射字段、检查结果、确认再写入。支持访问入口、服务器、数据库及其他资源、服务、运行作业和备份策略；账号或部署节点的独立批量录入以已选所属对象／服务和环境为上下文。对象行可顺带录入首个地址与首个账号，更多地址和账号继续在详情维护。

提供清单和资料卡两种预览方式：清单一行一对象，资料卡将字段／值映射到一个对象；不凭“两列”就最终确定对象数量。优先保留表格单元格边界及格内换行，兼容制表符文本。合并单元格和异常行给出校对提示；没有可靠结构时不猜测继承值。表外章节、重复表头、多个表混贴需要在预览中明确处理，不将它们静默变成对象。

多 IP 或端口、多个任务名的格内文字原样保留，不把换行或顿号自动拆成多条对象。只有在用户明确映射后才建立关联，不按节点号、IP 或同名条目自动绑定服务器。

疑似重复在预览中标记，默认待处理，由用户跳过或明确新增独立记录。发生名称冲突时给出可编辑的区分名称，确认后另建，不改写原件。新多范围记录的名称校验考虑适用范围重叠，不借升级之机合并或改名已有合法记录。

密码列明确映射至账号凭据，预览默认遮蔽，通过既有主密码和加密能力保存；不把已映射的密码写入备注、普通附加字段、日志或持久化预览。未明确映射的列必须确认用途或跳过。未提交预览仅在本次窗口内保留，失败保留输入供重试，离开时说明未提交状态。

本次勾选的行先全部校验；有错误时可以修正或取消勾选错误行，再整体保存其余所选行。提交、账号建立和秘密保存作为同一批次，取消解锁或写入失败不留下半批对象；重试不重复建立已提交记录。成功后显示创建、跳过及待处理数量。

### 导出、升级与备份

系统资料包纳入新资源字段、适用环境、标签、服务状态、独立节点、运行作业、备份策略及相关系统文档。一个共享对象完整导出一次，其他位置通过范围或索引引用；文档仍各自独立输出，另附系统总览，继续支持 Markdown、DOCX 和 PDF。系统中的项目历史仍出现在总览，任务文件只显示当前系统和独立的任务历史说明，不再显示可编辑项目绑定。

密码、Token、私钥沿用已确认的导出选择与解锁规则，导出仍用于阅读交接，不作为完整恢复格式。完整加密备份则包含全部新数据和引用；未提交的表格预览不进入普通备份。

旧版已支持的资料和备份升级保留条目身份、秘密、图片、收藏、文档和任务时间；旧单环境映射为原环境的适用范围，原系统通用记录继续通用。旧单条部署转为可继续编辑的节点，不猜服务器；旧任务按确认规则冻结历史并保留已有系统。升级或恢复失败保留原资料，不能丢失或隐藏旧任务，也不要求为普通资料迁移额外解锁秘密。

## 已确认的任务配套规则

列表、首页和搜索改用系统名称及系统范围；工作回顾保留月度，项目维度改为系统，回顾跨度口径不变。项目归档不再隐藏任务或阻止任务重开，旧任务不再阻止项目归档；项目管理入口从任务页移到台账，继续服务于系统的阶段历史与文档。上述规则同步适用于新建、快录、详情、草稿、回收站、导出及旧资料恢复，不能只删除选择框。

任务页提供全部系统、未关联系统及具体系统的筛选，保留未完成、已完成和全部状态切换，列表副标题显示系统。系统筛选继续排除于窗口拖动区域，使用原生鼠标也能展开和切换。

### 任务正常与紧凑布局

2026-10-19 用户新增要求：工作任务提供“正常／紧凑”布局切换，现有布局作为正常布局，默认继续使用正常布局。正常布局保留标题与系统、日期分行展示；紧凑布局每个任务只占一行，完成勾选、标题、可选系统和日期在同一行排列，不展开 Markdown 正文。

长标题在紧凑布局中单行省略，可点开详情查看完整标题和内容。窄窗口优先保证完成操作和标题可用，必要时隐藏日期等次要信息，不把单个任务折成多行。完成仍取当前时间，点击标题打开详情，不误触完成。

两种布局共用同一份任务、状态切换、系统筛选、搜索、排序和完成行为；切换布局只改变展示，不改写内容、系统归属或时间。布局选择按本机偏好记忆，未设置时采用正常布局。任务仍只可选关联系统，不恢复项目绑定。

旧项目、环境和资源背景保留为任务历史说明，不作为新的任务绑定，不因之后调整或删除台账对象而改变历史说明。旧有系统关联不自动改写，无系统者不按项目名或系统当前项目推断。决策见 [ADR 0007](../../docs/adr/0007-system-only-work-tasks.md)。

## 验收场景

1. 名称即可新建入口、服务器、数据库、服务、运行作业或备份策略；补字段可后做，系统与范围从当前页面带入。
2. 一份 GitLab 资料适用于两个环境并带地点／网络标签，编辑地址或账号后两处同步；独立部署的同名工具不被自动合并。
3. 移除一个适用环境后，对象、其他范围、账号和秘密仍保留；删除整个对象和删除环境的影响清楚，引用未处理时不丢相关资料。
4. 服务器硬件与附加资产资料、数据库实例／多个库名／主备及多账号可重启保留，普通查询不要求解锁。
5. 一个服务在生产有多个独立节点，各有端口和备注；部分绑定服务器，部分仅有节点名，按需数量可记录而不生成虚构机器。
6. 运行作业与备份可只记名称，也可关联一个对象和系统文档；失效／停用及待确认状态可检索，与个人任务状态独立。
7. 粘贴有表头的服务器清单得到多条记录，粘贴数据库字段／值资料卡得到一条记录；同为两列的组件清单可以切回逐行录入。
8. 合并单元格、格内多行地址、重复表头和多个任务名不会静默错位或被拆成假记录；异常行可修正或跳过。
9. 重复项与名称冲突可在预览处理，明确新增创建独立记录，不覆盖已有字段或秘密；密码列遮蔽并加密保存。
