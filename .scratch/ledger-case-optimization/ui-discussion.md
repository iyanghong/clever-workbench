## 现状核查

结合当前代码与已有虚构资料截图检查，主要问题如下。未操作用户的真实资料或运行中的应用。

| 当前事实 | 使用上的影响 |
| --- | --- |
| 一级分类为访问入口、服务器、环境台账；环境内又分资源、账号、服务，资源仍含服务器 | 同级概念混用，找一个对象前要先记住它被放在哪层 |
| 全局导航默认宽 228 px，系统列表再占 250 px | 查询内容长期让出较多宽度，窄窗口更容易被压成纵向表单 |
| 条目列表后直接接编辑表单，再接账号列表、账号表单和相关工作 | 查阅与维护混排，条目越多，详情和账号越靠下 |
| 系统、环境、对象和账号各有常驻新增输入、保存状态及相关操作 | 动作作用范围主要靠位置区分，视觉主次不清 |
| 范围筛选和修改对象环境的下拉框同屏；切换系统或分类会重置部分视图状态 | 筛选和改资料的含义容易混淆，返回后需要重新定位 |

## 已确认的主结构

保留一条全局导航，把系统切换放在工作区顶部，释放常驻系统列表所占空间。系统切换器可搜索，提供最近／常用系统，切换后恢复该系统上次的分类、筛选和位置。用户已通过 Q12 确认。

资料类型与环境分开：分类回答“我要找什么”，环境和标签回答“在哪个范围查”。用户通过 Q14 确认七个直接入口：访问入口、账号、服务器、数据库／中间件、应用部署、运行维护、文档。服务器只保留一个明确入口。账号页是当前系统各类账号的汇总视图，仍显示其所属对象，不新建独立的账号副本。

分类栏和环境筛选保持固定位置，结果区承载当前清单；切换分类不会修改对象归属。没有环境的系统仍可记录已支持的系统通用资料。

## 浏览、详情与编辑

主区默认展示清单，不自动展开第一项的编辑表单。入口行显示常用地址和账号目标；服务器行显示名称、IP、用途等查询字段；账号行显示用途、用户名、所属对象和适用环境。常用复制、打开操作就近提供，次要动作放在更多菜单中。

点击记录才打开右侧详情，保留清单的筛选、选中和滚动位置。宽窗口并排，内容不足以容纳清单与详情时采用覆盖面板，不挤出第四列或把字段缩成很窄的一列。

有账号的条目在详情中优先展示账号及复制操作，硬件、目录等配置按需展开；多角色账号始终标明用途、用户名和所属对象。查看秘密和复制秘密沿用现有解锁机制，普通查阅保持可用。

用户已通过 Q13 确认默认只读，点击编辑后允许修改并自动保存，保留明确的失败状态和重试；切换或关闭前完成保存，失败不丢内容。账号秘密仍使用既有明确的秘密保存操作。

各清单只展示查找所需的列：入口优先名称、地址和账号；账号优先用途、用户名、所属对象和范围；服务器优先名称、IP、用途及账号数量。硬件、路径、完整说明和相关资料放在按需详情中。列表行与详情的账号动作均明确显示角色和用户名。

首次进入可从访问入口开始，之后恢复上次的系统、分类、环境和查询位置；首次进入不自动选中第一条记录。关闭详情不清空清单状态，普通查看不会出现可编辑输入框。窄窗口采用覆盖式详情，保留返回清单入口；宽窗口并排显示，避免将主体清单压得过窄。

## 动作与低频资料

新建入口根据当前分类提供默认动作，快录只突出名称和少量常用字段，其他项展开；粘贴表格可从同一区域进入。移除各个分区常驻的新增输入，保留快捷键及全局其他新建动作。

系统名称用于识别当前工作区，系统说明、当前项目、项目沿革和导出在系统信息或相关操作中集中管理，不插在每份条目清单的上下方。任务与文档提供相关入口，不在系统、环境和资源三个层次同时堆放整块相关工作表单。

台账返回上次查询位置；首次进入的默认视图及快捷入口随布局方案一并确认。全局工作台继续承接常用对象和个人待办，避免台账再多一层必须经过的统计概览。

## 视觉方向

延续 macOS 风格：导航与浮层使用克制的半透明材质，数据区域保持稳定底色；用行间距、字体层级和细分隔表达关系。主要文字保持清晰，避免过小浅灰标签、大片空白表单及层层卡片；选中态使用统一强调色。

Apple 的[材质指南](https://developer.apple.com/design/human-interface-guidelines/materials) 将 Liquid Glass 用于导航和控件的功能层，并建议克制使用，不将内容区全部玻璃化。这里据此选择导航有层次、内容优先可读的方向，不把材质效果作为解决信息层级问题的手段。

## 页面示意核对

以完全虚构的系统、地址和账号展示同一工作区，供讨论清单密度和详情排列；不使用案例原文中的账号、密码或地址。可以体验顶部搜索切换系统、七类资料切换、环境和标签筛选，以及记录详情、普通字段编辑和快捷新增。复制和打开操作只展示动作说明，示意不保管真实秘密。

服务器示意清单保留名称、IP、用途和账号数量；详情优先展示多角色账号，操作系统、CPU、内存和硬盘按需展开。账号示意汇总其所属对象的账号，不建立第二份记录。系统说明、项目关系和导出入口集中在系统信息中。

宽窗口并排显示清单和详情；窄窗口用详情替换清单视图，通过“返回清单”恢复查询。已检查虚构资料下的分类、筛选、切换系统、普通字段保存和快捷新增交互，并查看宽、窄窗口及明暗外观。检查仅针对讨论用示意，不代表应用功能已实现或通过验收。

列表行高与详情宽度仍可调整，当前分别以 68 px 和 320 px 展示。它们是讨论起点，不作为已确认的尺寸要求。
