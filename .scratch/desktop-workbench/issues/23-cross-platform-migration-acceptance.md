## 交付行为

证明 Mac 与 Windows 的完整资料可以双向迁移，并将用户可安装的首版产物、验收结果与使用边界一同交付。

## 前置依赖

- [21：macOS 安装包与完整工作流验收](21-macos-personal-release.md)：需要实际运行验证过的 Mac 产物及其生成的完整备份。
- [22：Windows 11 x64 安装包与运行验收](22-windows-personal-release.md)：需要实际运行验证过的 Windows 产物及其生成的完整备份。

## 本任务边界

是依赖真实双平台产物的交付验证，不补造新功能或替代各功能自己的测试；发现失败时修复对应能力并重新验证受影响路径。

## 验收标准

- [ ] 在独立资料位置完成 Mac 到 Windows、Windows 到 Mac 两条实际恢复路径，使用备份生成时的主密码且不复制原机器系统密钥。
- [ ] 双向迁移后系统历史、当前项目、环境部署、多角色账号、任务状态与时间、文档、图片、草稿和回收站引用完整。
- [ ] 恢复后能继续编辑、重新锁定与解锁、再次备份并在另一平台恢复，避免只验证一次静态导入。
- [ ] 正确验证旧密码备份与新密码备份的使用方式；错误密码、损坏包或取消恢复均保留目标机原资料和必要回退副本。
- [ ] 明确记录各平台已执行与未执行的验收项，只有实际证据满足时才标记首版完成；不承诺未验证的其他架构或系统版本。
- [ ] 交付对应平台产物及精简的安装、主密码、备份与恢复说明，说明本地普通资料和秘密字段的不同保护范围。
- [ ] 产物与示例中不包含真实用户资料或凭据，首版不附加未要求的云同步、插件安装或自动更新能力。

## 演示与验证

Mac 导出后在 Windows 用对应主密码恢复并继续编辑，再从 Windows 导出回 Mac；检查新旧资料、图片和秘密均符合预期。

以真实双平台备份交换为最终可观察结果，针对失败路径补验证，避免仅根据代码或构建日志宣称兼容。


## Answer

Mac→Windows Server 2025→Mac的真实备份往返已经通过，最终Mac安装包也已再次恢复Windows返回备份、继续编辑并导出。两种安装包和说明已提供，资料均为虚构。由于前置任务22的Windows 11目标验收缺少环境，本任务保留未验收状态，不将Server结果标记为完整首版交付通过。
