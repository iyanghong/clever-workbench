## 交付行为

在系统环境或具体资源下维护超管、业务角色等多个账号，快速查询用途、用户名和归属。

## 前置依赖

- [05：资源台账与轻量复制](05-resource-ledger-copy.md)：需要实际资源及其环境归属，才能完整验证两种账号挂载位置。

## 本任务边界

只交付账号元数据，用户名允许为空；秘密的保存、查看与复制必须等待任务 12、13，不能暂时落为普通明文。

## 验收标准

- [x] 系统环境和具体资源均可新增多个账号，用途或角色标识即可建立，用户名和说明可后补。
- [x] 用户名允许为空，能表达只使用 Token 或密码的身份；同一归属可以区分多个用途，而不引入工作台多用户权限。
- [x] 新增账号自动带入当前归属并清楚展示系统、环境、资源；修改归属时验证目标有效且不发生跨系统误挂。
- [x] 普通字段可直接修改和复制；复制账号创建新身份，默认仅复制非秘密信息。
- [x] 普通账号查询返回元数据，不预留明文秘密在快照、列表或日志中；尚未实现的秘密操作不可用且不会假报成功。
- [x] 系统、环境、资源改名后账号继续可定位，重复显示名称通过上下文区分；持久化和无效目标的失败行为可验证。
- [x] 用两类挂载位置、多角色和空用户名场景验证公开操作，并为后续秘密能力保留明确的操作边界。

## 演示与验证

在系统 A 的生产环境建立超管与 B 角色账号，再为 Redis 建立独立访问账号，分别复制用户名。

验证账号元数据从创建到列表、详情、复制和重启的完整路径；避免用临时明文方案等待后续补加密。


## Answer

环境和资源账号共用同一面板，支持多角色、空用户名、普通复制及同系统归属调整。账号不含明文秘密字段，复制明确列出普通字段。公开存储测试覆盖两种归属、跨系统与错误环境拒绝、资源删除保护、重命名及重启；Electron 流程覆盖超管／B 角色／Redis 账号、复制用户名、创建副本、归属调整与重复名称的就地错误提示。类型检查与构建通过，实际截图已检查。
