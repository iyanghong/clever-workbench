# 10：项目归档与长期资料继续维护

Status: ready-for-agent
Blocked by: 06, 09

当前阶段：任务拆分已确认。实施授权：用户已明确要求直接编码，按依赖自主执行至完成。

共用完成标准见 [拆分总览](../ticket-plan.md)。

需求依据：[正式需求规格](../spec.md)；用户故事 US-39、US-40、US-41、US-42；测试场景 T02、T06。

## 交付行为

归档结束的项目并保留历史，长期系统和账号所属资源继续可维护；在恢复、重开与回收站恢复时保持一致的项目状态。

## 前置依赖

- [06：系统与资源下的多角色账号](06-multi-role-account-ledger.md)：需要已经可维护的环境与资源账号，才能验证项目归档后账号元数据仍然可用。
- [09：独立文档与创建时上下文](09-documents-context-links.md)：需要项目、真实任务、长期系统、资源和独立文档全部可操作，才能证明归档只收起阶段工作而不冻结台账。

## 本任务边界

沿用原有任务归档约束，并补齐系统当前项目和文档历史关系；不将系统、环境或资源随项目级联冻结或删除。

## 验收标准

- [ ] 有未完成任务时归档被阻止并说明原因，用户可处理或转移任务后再归档，不将待办隐藏到归档区。
- [ ] 归档项目从日常项目范围收起，但历史任务与文档可查阅；项目可恢复且身份保持。
- [ ] 归档不冻结系统、环境、资源及其账号元数据，仍可正常查询和维护。
- [ ] 若归档项目是系统当前项目，清除当前标记并保留历史关系，不猜测或自动改成其他项目。
- [ ] 归档项目中的任务重开须明确同时恢复项目；未完成任务从回收站恢复时明确选择恢复项目或转为未分类。
- [ ] 状态变更作为完整业务操作保存，失败不留下项目已恢复但任务仍错误、或当前标记悬空等中间状态。
- [ ] 以含任务、文档、资源和当前项目的资料验证归档、恢复、重开及重启，检查历史关联不被重写。

## 演示与验证

先尝试归档有未完成任务的 A 项目，处理任务后归档；继续更新生产 Redis 与账号用途，查阅 A 的文档，再恢复项目并重开任务。

复用已有归档、重开和回收站约束用例，增加长期系统与文档在归档后继续工作的外部验证。
