Blocked by: 01

## 交付行为

选择浅色、深色或跟随系统，并让窗口、界面材质、动态效果和键盘焦点响应平台与可访问性设置。

## 前置依赖

- [01：独立桌面应用与任务快录](01-desktop-task-capture.md)：需要真实桌面窗口、应用布局和本地持久化能力，才能贯通设置与系统偏好对用户操作的实际影响。

## 本任务边界

交付从系统事件和用户设置到界面表现的完整路径，作为所有后续模块共用的行为；不把全部页面设计拖到本任务才开始。

## 验收标准

- [x] 用户可选择浅色、深色和跟随系统，设置持久化；跟随模式响应系统变化，手动选择不会被系统事件覆盖。
- [x] macOS 27 的导航与操作材质有清晰层次，正文和密集资料底色保持对比，透明效果有可读的回退。
- [x] 减少透明度、增强可读性和减少动态效果能通过平台能力或应用明确设置生效，不影响功能操作。
- [x] Mac 与 Windows 的窗口按钮、菜单和快捷键遵循平台习惯；页面可通过键盘导航，焦点可见、顺序合理并在弹层关闭后返回。
- [x] 共用外观与交互规则可被新模块沿用，后续任务必须使用这些规则；不新增与实际页面脱节的主题演示应用。
- [x] 通过设置、系统事件和重启检查真实结果，记录浅色、深色及可访问性状态的视觉核查证据；目标平台完整页面由交付任务验收。

## 演示与验证

切换浅色、深色和系统主题，重启保持偏好；开启减少动态效果或透明度，再仅用键盘完成任务快录。

以真实窗口和已有任务流程验证偏好，不测试 CSS 文本或固定组件树；不因平台材质不同而牺牲可读性。


## Answer

全局外观响应用户主题、系统媒体查询及原生偏好事件。应用提供减少透明度、增强对比和减少动态效果开关并持久化；系统已启用的偏好仍优先生效。Mac 关闭材质时同时禁用原生 vibrancy，正文保留实色背景，Windows 保留原生窗口边框。共用 Dialog 显式恢复触发控件焦点，所有可聚焦元素有可见轮廓。2 项 Electron 外观／键盘测试通过，涵盖系统主题模拟、原生偏好 updated 事件边界、重启和键盘快录；浅／深／高对比截图保存在 ../evidence/。4 项恢复测试确认偏好随备份迁移。Windows 实机和打包产物视觉验收仍属于任务 21／22，未据此声称已验证。
