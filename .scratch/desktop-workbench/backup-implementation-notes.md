# 任务 16–19 实施接续

现有 electron/backup.ts 仍是普通 ZIP：一致 SQLite 快照、引用附件清单、分段校验、隔离预检、CURRENT 指针恢复与回滚可继续复用。整体加密必须替换导出的普通 ZIP，不能并存一个未经提示的明文导出入口。现有文件扩展名和默认文件名仍有 cleverplan，须改为 .cwb / Clever-Workbench。

## 加密容器

- 公钥封装：使用 vault-crypto.ts 中同一份数据库快照的 VaultConfig；RSA-3072 OAEP 显式 SHA-256 封装新随机 32 字节 AES 密钥，AES-256-GCM 加密完整 ZIP，随机 12 字节 nonce、16 字节认证标签。
- 建议容器布局为 magic、4 字节 header 长度、JSON header、密文、末尾 tag。头部包含版本、算法、VaultConfig 保护材料、被封装的 AES 密钥和 nonce。将原始前缀字节用作 AAD。头部最多约 16 KiB，认证前也验证固定 KDF 参数、密钥长度、版本与文件大小。
- 导出将 ZIP 流直接送入 cipher，再写临时密文文件；不要另外保留明文 ZIP。先写 header、追加管线密文、append tag、fsync，最后 rename。锁定导出仅用公钥，不调用秘密解锁或 read。
- 预检先用备份生成时的密码解开 header 中备份私钥，再 OAEP 解开 AES 密钥。完整认证通过后才能解压隔离的临时 ZIP；错误密码、篡改或不支持版本清理临时文件。通过预检后只保留隔离数据库／附件及无明文密钥的准备令牌。
- Header 的 VaultConfig 必须来自同一个 SQLite 快照，不能从可能已轮换的活动数据库另读一份，避免密码代次不一致。主进程可禁止备份／恢复期间轮换主密码。

## 界面与可信边界

- 推荐把设置从 TaskWorkspace 提取为独立 SettingsPage，后续任务 20 的共用外观偏好也在此维护。删掉 TaskWorkspace 中不可达的旧设置／备份流程，保持单一入口。
- 手动导出：若尚未设置主密码，复用 VaultProvider 初始化；已有保护时不要要求解锁，锁定也能导出。
- 选择备份与输入密码分两步：主进程原生文件选择后返回随机令牌和 basename，路径保留在主进程；renderer 提交 token＋备份密码。错误密码允许重试，取消／过期清理 token。禁止 renderer 直接传任意文件路径。
- 预检结果应显示项目、系统、资源、账号、秘密、任务、文档和图片数量，随后才确认真正恢复。预检不修改当前库。
- 未设置主密码时自动备份不运行、不记录假成功；设置显示“未启用／设置主密码后启用”。自动备份仍按有变更每日一次、保留 7 份。

## 恢复与轮换

- 当前库有主密码时，恢复前副本使用当前库自己的保护材料。新设备当前库尚无主密码时，可用已认证的导入包公钥及对应便携材料保护恢复前普通资料副本；这份副本用导入包密码恢复。无需先另设一遍主密码。
- 在指针切换前保留完整恢复前副本，验证后才切换；失败恢复原目录与数据库句柄，保持原资料可用。保留本机备份目录，重置备份成功时间／revision，避免恢复被误记为新备份成功。
- 恢复前锁定 Vault，成功后更新 VaultStatus；Vault 内部通过 Store 引用获取当前 DB，不缓存旧句柄。
- 主密码轮换必须生成新 DEK 与新 RSA 密钥对，重加密当前所有秘密；事务提交新密文和配置，失败全部回滚。旧备份保持旧材料和旧密码。不能仅重包同一 DEK，否则旧密码＋旧备份材料还能解当前新秘密。
