实现与相关验证已完成，详见[实施记录](implementation.md)。下方调查记录描述实施前状态，不代表当前仍存在相同缺口。

## 实施前核实的现状

现有[台账工作区](../../src/features/ledger/LedgerWorkspace.tsx)已接入[粘贴表格弹窗](../../src/features/ledger/PasteLedger.tsx)，不是未使用的旧组件。用户可以从 Word、Excel 粘贴表格或输入制表符文本，映射字段并校对后批量新增。相关规则已有[需求规格](../ledger-case-optimization/spec.md#表格粘贴与校对)。

- 支持访问入口、服务器、数据库、Redis、其他资源、服务、运行作业、备份策略、账号、部署节点；不支持批量创建系统或环境。
- 每批固定一个系统、一种类型和一个环境；独立账号需选择所属对象，部署节点需选择服务及环境。
- 现有预览仅名称可直接编辑；地址、端口、用户名、密码、备注等需调整源表格并重新粘贴。没有空白多行录入表格，也没有 CSV／XLSX 文件选择入口。
- 所选行每次最多 200 条；疑似重复须跳过或确认新增独立记录，不自动合并或覆盖旧资料。
- 密码列明确映射后遮蔽展示，并随账号加密保存；主进程整批校验、事务保存，并使用批次标识避免同次重试重复创建。

现有调用链为 `PasteLedger → DesktopAPI.captureLedgerBatch → preload → ledger-batch → vault.captureBatch → SQLite`。入口契约见 [types.ts](../../src/types.ts)、[preload.ts](../../electron/preload.ts)、[main.ts](../../electron/main.ts) 与 [vault.ts](../../electron/vault.ts)。

以上结论来自静态代码核查，未在本轮运行应用或测试。当前工作区已有的 `.scratch/workbench-efficiency/`、`docs/资料/` 和调查期间出现的 `tests/e2e/system-export.spec.ts` 改动均不属于本轮写入范围。

## 已确认的功能目标

用户进入一个系统后，可选择台账类型，直接在表格中填写多条资料；也可粘贴已有表格，映射字段后逐格修改，再统一提交新增。批次是一次录入操作的范围，不引入新的长期业务对象，也不改变系统、环境、资源、账号等既有领域含义。

覆盖范围是访问入口、服务器、数据库、Redis、其他资源、服务、运行作业、备份策略、账号与部署节点。具体字段、范围、关联和未提交内容处理按以下已确认规则实施。

### 已确认的交互规则

以下沿用现有批量新增边界，不增加批量更新或新的业务对象：

- 每批最多 200 条待新增资料；名称即可起步，按对象类型补充资料。部署节点仍须服务和环境，独立账号仍须所属对象。
- 表格提供增加行、删除行及勾选／取消勾选；全空白行不提交，已填写其他字段但缺名称的行给出错误，不能静默丢弃。
- 每类现有批量字段均可直接修改，普通字段保留多行文本；密码使用遮蔽输入，沿用现有专用加密与解锁边界。现有 TSV／HTML 表格解析、字段映射和未知列确认继续使用。
- 疑似重复由用户取消勾选或明确新增独立记录，已有唯一性约束仍有效；不自动合并、覆盖或按地址建立关联。
- 所选行全部校验通过才提交；可修正或取消勾选错误行。所选记录、账号和密码作为同一事务保存，失败不留半批，重试不重复创建。
- 关闭录入窗口、切页、退出应用和安装更新均应遵守 Q7；自动保存协调不得擅自提交尚未确认的批次。
- 沿用台账现有入口位置，入口名称调整为“批量录入”，默认带入当前分类与已确认的系统／环境背景；含多个具体类型的分类提供明确的类型选择。保留键盘操作、窄窗口、主题和焦点行为。

现有批量字段：

| 对象 | 可直接编辑的资料 |
| --- | --- |
| 服务器、数据库、Redis、其他资源 | 名称、地址、端口、说明、用户名、密码、账号角色、附加字段 |
| 访问入口 | 名称、一个地址、说明、用户名、密码、账号角色 |
| 应用／服务 | 名称、代码仓库、说明 |
| 运行作业、备份策略 | 名称、频率、状态、说明 |
| 账号 | 名称／角色、用户名、密码、说明 |
| 部署节点 | 名称、地址、端口、说明、节点数量、部署方式 |

### 实施前核实的领域限制与缺口

资源、入口与服务原有详情可选择多个适用环境和标签；运维只可属于一个环境或系统通用，另可带标签。账号没有独立适用范围：资源／入口账号继承所属对象的范围，系统账号归属一个具体环境。节点固定属于一个服务和一个环境，不另建独立标签。这些规则已有领域定义，本次不改变其含义。

当前批量入参只有单个 `environmentId`，没有多环境和标签；服务批量保存尚未使用所选环境。按已确认的 Q4 规则，应在新增服务的同一事务中正确保存所选范围，避免界面显示已选择环境而资料仍成为系统通用。

当前 `PasteLedger` 的取消、关闭和 Esc 有未提交提醒，但没有注册保存协调；原生退出和更新不能据此识别未提交内容或在途提交。需复用 `useSaveGroup` 和既有 `Dialog` 补齐边界，不通过自动保存触发整批新增。此缺口为静态代码核查结果，尚未实机复现。

## 决策收敛与验收

Q1～Q7 全部确认，访谈结束并获准实施。文件导入、混合类型、跨系统、逐行切换归属、批量设置标签与多环境、持久化录入草稿均不在本次范围。

1. 在当前系统和分类打开批量录入，手填多行并添加或删除行；10 类对象均能使用各自的现有字段，空白行跳过，部分填写的错误行明确提示。
2. 手填记录后粘贴表格，保留旧值，新增行可逐格修改；映射未知列、合并单元格、重复表头及密码列遵守现有校对边界。
3. 账号和部署节点的归属正确，服务保留所选环境；修正范围后重复提示与当前资料一致。
4. 提交失败保留输入且无部分写入；重试和连续点击不重复新增；成功显示创建与跳过数量，清理暂存内容。
5. 关闭、Esc、应用退出及全局保存检查不会静默丢弃或提交草稿；提交中的操作等待结束。验证明暗主题、正常及窄窗口、键盘焦点和长内容滚动。

术语尚未形成新定义，因此暂不修改 [CONTEXT.md](../../CONTEXT.md)。仅当形成有实际取舍、难以逆转的架构决定时新增 ADR；界面与录入规则在本规格中记录。
