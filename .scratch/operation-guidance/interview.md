# 配置驱动的操作指引与发布编写规范

Status: resolved

日期：2026-10-21。当前阶段：设计访谈已完成，Q20 已确认完整方案，尚未进入产品实现。

## 用户目标

1. 建立操作指引规范，支持通过配置展示某项功能的操作指引。
2. 每次发布前，依据规范编写发布内容对应的操作指引。

## 已确认决定

- Q1：首版由维护者在仓库中配置指引内容与展示条件，随应用版本发布，支持离线查看。
- Q2：区分长期维护的“功能操作指引”和说明本次操作变化的“版本操作指引”，版本指引引用并复用对应功能指引。
- Q3：首版采用统一图文步骤弹窗，包含简短文字、必要截图和“前往功能”入口。
- Q4：每次发布提交面向用户的操作说明；新增功能或操作方式变化必须有对应指引。没有操作变化的修复、重构等，明确记录“无新增操作”及原因。
- Q5：功能附近提供手动指引入口，设置集中查阅；有操作变化的版本在升级后主动提示一次，无新增操作不主动弹窗。
- Q6：采用“用途、准备条件、功能入口、操作步骤、完成结果、常见问题”统一模板；每步一个明确动作及可观察结果，按需使用示例截图，不适用项说明原因。
- Q7：指引检查只提示问题，不阻止发布。此答案替代第二轮建议中的阻断规则；每次编写说明的内容要求仍保留。
- Q8：预先编写待发布说明，在发布时绑定实际版本及对应源码。
- Q9：同源生成 GitHub 用户更新摘要和操作入口，应用内显示完整步骤；完整提交清单保留为技术明细。
- Q10：版本指引实际成功显示后记为“已提示”；关闭、Esc 或重启不再次自动弹出，设置仍可手动重看。提示记录不代表用户已读完或学会。
- Q11：提示记录只保存在当前设备，独立于业务资料和加密备份；恢复旧备份不回退提示记录，换设备按首次启用处理。
- Q12：首次启用指引只介绍当前版本，不追溯全部历史；之后跨版本升级按整个升级范围汇总操作变化，同一功能合并，引用当前有效的功能指引。整个范围都没有操作变化时不自动弹窗。
- Q13：自动指引等待主界面就绪、正在编辑的内容保存完成，并避让其他弹窗及安装、恢复等流程；“前往功能”沿用保存与导航链路，保存失败保留当前内容。入口只导航，不代替用户执行业务动作。
- Q14：缺失或无效指引在发布检查中明确警告，应用忽略无效条目，缺图保留文字；无可展示内容时不弹空窗口，手动入口给出简短不可用说明，正常功能仍可使用。
- Q15：首批覆盖全部现有功能，替代“仅先做三组功能”的建议；按真实用户流程组织覆盖清单，不能以少量示例代替全部覆盖。
- Q16：采用统一 JSON 内容模板和仓库内截图文件，维护者填写文字、步骤、图片引用及预设功能入口；配置不包含任意脚本或 HTML。
- Q17：保留已发布版本操作说明，功能指引保持稳定标识并随新版本修订；设置默认查阅当前有效用法，也能查看历史版本摘要。历史引用使用当前有效入口，已移除功能明确标注且不能误跳转。
- Q18：本地发布与 GitHub Actions 都汇总指引警告，说明文件、问题及修正办法；维护者记录步骤、截图和入口的人工核对结果及已知缺项。缺失说明不能自动归类为“无新增操作”，未处理警告或缺少核对记录不阻止发布。
- Q19：后续实现以 macOS 安装版作为主要验收入口，覆盖离线、首次与跨版本提示、重启去重、备份恢复不回退提示记录、保存失败、弹窗避让、异常降级及指引警告不阻断发布；同时验证深浅主题、窄窗口、Esc 和焦点返回。
- Q20：用户回答“是，确认这份完整方案”，确认规范、26 组功能覆盖清单、JSON 模板及验收边界作为后续实现依据。

已确认术语同步到项目现有的 [CONTEXT.md](../../CONTEXT.md)，沿用仓库的领域术语入口。

## 现有实现事实

- 当前没有统一的操作指引配置、指引注册表或阅读记录。
- 共用 Dialog 已支持模态、Esc、关闭按钮与焦点返回，可供后续实现复用。
- 应用切页、打开搜索或新建前会等待保存；更新重启提示、备份及主密码另有弹窗，因此指引展示须定义时机和避让规则。
- 发布脚本基于远端 master 已提交源码准备版本，当前版本提交只更新两个包版本文件。
- GitHub Release 正文由上次正式发布之后的提交标题和链接生成，尚无指引编写、覆盖或引用校验。
- 本地发布预检与云端构建前都可接入同一指引校验；仅警告的方式、报告与人工核对规范均已确认，尚待实现接入。
