# 操作指引实施任务拆分建议

阶段：用户已确认粒度与依赖，并授权 implement-spec；11 项独立任务已生成，实施按依赖推进。

依据：[实施规格](spec.md)、[全量功能覆盖清单](coverage.md)及 Q1–Q20 的确认。此文为已确认任务图；正式任务各自成文，父规格在任务生成阶段保持原状。

## 拆分原则

- 每项交付可演示或验证的完整行为，包括必要内容、应用或发布入口、状态及相应测试，不把前端、主进程、JSON 和测试分别当成独立横向任务。
- 先通过应用更新指引完成最小实际流程，同时固定共享内容契约，之后扩展其他功能和版本说明。
- 未发现必须先单独开展的大范围机械重构；相关保存、弹窗及发布接口的必要整理在使用它的完整流程任务中先完成，不额外加入脱离用户行为的重构任务。
- 内容任务均交付实际正文、必要示例图片、功能附近与设置入口、正确跳转、操作核对及覆盖证据。每项使用隔离资料；只编写 JSON 或只接一个按钮不算完成。
- 不为“全部内容都完成”添加业务上不存在的前置依赖。跨任务引用只指向已交付条目，必要前置操作先有自足说明，最后统一校对复用关系；现有业务功能本身不依赖它的指引先被编写。
- 每项自带必要验证，总验收只补跨任务组合与最终安装包证据，不能把所有测试推迟到最后。

## 建议任务

### 01：离线指引阅读与安全导航

**依赖：无，可首先开始。**

交付：用户能从设置和应用更新功能附近打开真实的应用更新指引，离线阅读图文步骤、关闭重开并前往功能；形成后续指引复用的完整入口。

核对要点：

- 实现结构化内容、稳定标识、图片、平台及入口登记的共同契约，包含已确认的功能／版本内容格式约定；应用能容错加载实际内容，后续维护和发布沿用相同规则。
- 交付覆盖组 21 的完整应用更新正文，以及“如何查看功能指引”的使用说明；应用内提供统一查阅入口、步骤弹窗和受控导航。
- 先保存再导航，保存失败保留输入；无适用对象时安全进入选择入口；不自动执行业务动作，不绕过安装冻结或资料代次保护。
- 无效配置、缺图、失效入口及空内容能够降级，资源随包，断网和离开源码目录后仍能阅读。
- 验证深浅主题、长内容、窄窗口、Esc、焦点返回及原生鼠标关闭。必要的共享对话框和导航整理在本流程内完成。

规格用户故事：1–12、20、25、46、52–54；覆盖组：21。

### 02：版本历史与升级后一次提示

**依赖：01。**

交付：用户升级后在合适时机看到一次相关版本说明，并可在设置中重看历史；重启、恢复旧备份及跨版本升级按规范处理。

核对要点：

- 首次只考虑当前版本；后续跨版本合并尚待提示变化，同功能去重但不遗漏不同变化。目标版本无变化但中间有变化仍提示，明确无变化范围安静处理。
- 用户可手动查看当前及历史摘要，进入当前有效功能；已移除功能和历史缺口如实说明，不把草稿或失败发布当作正式历史。
- 主界面就绪、持续输入结束、保存成功且没有其他弹窗或恢复／安装流程时才自动显示；检查与打开之间不发生模态冲突。
- 实际成功显示后记录已提示；待显示时退出不消费提示，关闭／Esc／重启／降级再升级不重复，手动重看不重置记录。
- 主进程持有独立设备记录，备份恢复不回退记录；新设备、损坏记录与写入失败均有诚实且不反复抢焦点的行为。
- 在隔离安装版中验证状态转换与恢复场景，补齐“重看版本说明”的指引。使用受控版本夹具即可独立验证，不等待真实发布。

规格用户故事：13–24、52、55。此任务消费已约定的版本内容，正式发布数据由任务 04 产生。

### 03：发布预览与非阻断内容检查

**依赖：01。**

交付：维护者在本地发布预览与 CI 报告中看到实际内容、缺项、引用问题和核对记录状态；内容问题只警告，应用打包仍可降级继续。

核对要点：

- 使用共同契约校验有变化／无新增操作两种说明、功能关联、图片、入口、重复标识、占位文字及人工核对记录；缺少说明不推断成无新增操作。
- 输出具体问题、文件／字段和修正建议；本地与 CI 规则一致，保留全部可用问题和内容。
- 本地预览只检查实际计划远端源码，隔离本地未提交／未推送内容，不产生提交、tag 或外部发布副作用。
- 无效内容不因后续资源整理或应用打包而变相阻断；保留警告，不通过普遍忽略错误掩盖真正的代码构建问题。
- 用临时 Git 仓库和现有发布入口证明预览、内容降级及警告行为；同步维护者编写与核对说明。

规格用户故事：53–54、56、59–63。任务 01 负责应用中的容错阅读，本任务交付维护者可观察的检查与预览入口。

### 04：实际版本绑定与同源发布正文

**依赖：03。**

交付：一次发布准备把待发布说明绑定实际版本和源码，产生应用所需版本内容及同源 GitHub 用户摘要；版本占用和失败重跑不混入其他源码的说明。

核对要点：

- 发布准备的允许变更范围明确包含版本记录，与版本号变更一致生成，保留人工核对来源；不把提交自身 SHA 写回同一提交。
- 只使用计划远端源码；版本提交使用实际本地身份及中文说明，不混入既存草稿、未提交文件或未推送内容。
- 目标版本号调整后重新绑定；固定 tag 重跑读取固定内容；对草稿、失败版本和正式历史保留清楚来源，历史缺口不编造。
- GitHub 正文包含用户摘要、操作入口、技术提交和来源；应用版本内容源自同一数据。缺失内容使用诚实的不可用说明。
- 验证从内容警告、准备、摘要生成到构建输入的完整链路仍可继续；既有身份、版本和资产安全失败继续失败。
- 通过临时仓库、云端发布适配入口和打包产物核对证明行为；不为验收向真实仓库发布损坏版本。

规格用户故事：55–58、60–64。无需等待任务 02 的自动提示界面完成；二者使用任务 01 的共同契约，最终由任务 11 验证组合。

### 05：日常工作流程指引

**依赖：01。**

交付：用户在工作台、搜索／新建、任务、文档和工作回顾中获得完整、可实际操作的指引。

核对要点：

- 覆盖组 01、02、12、13、14：首页常用入口与菜单，九种新建和搜索，任务草稿／计划／标签／批量归属，文档编辑与本地图片，工作回顾。
- 功能附近及设置中的入口一致可达；导航保留必要背景和保存行为，编辑器说明复用而不复制维护两套相同内容。
- 明确项目不是任务必填归属、秘密不参与搜索、工作回顾是日历跨度等领域边界。
- 逐项实际核对正文、入口、结果和取消路径，必要截图只用隔离示例资料；验证代表性的窄窗口和键盘操作。

规格用户故事：26–27、37–39；覆盖组：01、02、12、13、14。

### 06：系统、台账查阅、访问入口与账号指引

**依赖：01。**

交付：用户能按指引管理系统和环境／项目关系，浏览复制台账，维护访问入口及账号。

核对要点：

- 覆盖组 03、04、05、07：系统与环境、项目档案和沿革、分类筛选列表详情、范围标签、单条／多条复制、多地址、账号秘密及归属调整。
- 从真实菜单和对象详情打开对应指引，缺对象背景时进入选择流程；指引不擅自切换对象或执行复制、解锁、删除。
- 说明同系统复用与跨系统复制、秘密显式选择、项目归档影响和账号归属约束。
- 在隔离资料中完成含账号／秘密及取消／失败路径的核对，相关记录不含真实秘密。

规格用户故事：28–30、32；覆盖组：03、04、05、07。

### 07：资源、部署、运维、批量录入与导出指引

**依赖：01。**

交付：用户能按指引维护资源和部署、记录运行维护、校对批量录入并导出系统资料。

核对要点：

- 覆盖组 06、08、09、10、11：资源字段与账号、服务和节点、运行作业与备份策略、各支持类型的表格粘贴、系统导出。
- 指引入口接到对应分类与操作附近；前往功能只导航，实际创建、提交或导出仍由用户完成。
- 导出正文依据最终实施源码核对内容选择、任务开始日期与输出形式，不把未合入功能写成已存在。
- 明确导出与完整备份的区别、秘密明文输出、删除引用限制及批量校对责任。
- 提供实际流程核对与必要截图，验证表格映射／取消和导出前保存／解锁说明。

规格用户故事：31、33–36；覆盖组：06、08、09、10、11。

### 08：外观、凭据保护与回收站指引

**依赖：01。**

交付：用户能在相应入口查看外观调整、可选主密码及任务／文档删除恢复的完整说明。

核对要点：

- 覆盖组 15、16、17：任务与文档各自的回收站，主题与辅助外观，系统保护和主密码的启用／解锁／锁定／更改／关闭。
- 功能入口与集中查阅互通；秘密保护说明正确区分普通资料与秘密、主密码与备份密码。
- 不宣称文档有不存在的批量清空，或所有台账删除均可从回收站恢复。
- 在隔离资料中核对恢复／永久删除确认及主密码操作取消路径；界面遵守当前外观偏好。

规格用户故事：40–42；覆盖组：15、16、17。

### 09：备份、迁移与更新失败处理指引

**依赖：01。**

交付：用户能完整查阅备份密码、手动／自动备份、恢复换机和更新历史／失败处理，并理解不同恢复材料的用途。

核对要点：

- 覆盖组 18、19、20、22；更新操作本身复用任务 01 已交付的组 21。
- 说明独立备份密码、历史备份密码、取消配置、自动备份保留规则、预检与整份恢复以及目标解锁条件。
- 更新历史说明涵盖日志、备份／旧应用定位、系统隔离与授权、成功清理和失败保留；不将人工恢复或下载完成称为自动健康成功。
- 根据 ADR 0011 同步校正过时的根规范及使用文档密码口径，不改变密码实现或历史备份规则。
- 用隔离资料核对成功、取消和失败步骤，记录实际证据；不重做不在本任务范围内的真实更新器安装验收。

规格用户故事：43–45、47；覆盖组：18、19、20、22。

### 10：ZIP 文本归档四种模式指引

**依赖：01。**

交付：用户能分别按指引完成文件归档、Git 筛选归档、分片目录还原及剪贴板还原，并从工具页或首页常用入口找到帮助。

核对要点：

- 覆盖组 23–26，分别提供短流程和准确准备条件；共享的分片、密码、输出及后台运行规则可以复用。
- Git 模式明确“按提交选择文件路径，读取当前磁盘内容”，不宣称获取历史文件或自动联网拉取。
- 目录与剪贴板模式覆盖完整分片、错误密码、重复／异常片、输出及不覆盖已有目标的说明。
- 只用隔离示例文件核对四种模式和取消／失败结果，解释后台切页与退出限制及本次密码不保存。

规格用户故事：48–51；覆盖组：23、24、25、26。

### 11：安装版全流程与内容覆盖验收

**依赖：02、04、05、06、07、08、09、10。**

交付：在同一 macOS 安装包中验证全部内容、版本提示和发布生成物组合可用，形成逐项覆盖及实际验证结果，明确任何残留缺项。

核对要点：

- 26 组覆盖清单每一项关联实际指引及步骤，补齐指引功能自身说明；独立记录正文完成度和机制完成度，不按标题数宣布完成。
- 检查跨组引用、入口、词汇和平台说明，确认必要图片来自包内，断网可读。
- 从发布绑定生成物进入安装版，验证真实包版本、应用内历史及 GitHub 摘要的同源关系；自动提示、恢复设备记录和保存避让的组合符合规格。
- 验证深浅主题、正常／窄窗口、长内容、键盘焦点、Esc、辅助外观与原生鼠标关闭。
- 使用隔离异常内容通过预览、检查、生成及打包链路证明非阻断策略，同时确保原有安全与构建错误仍失败。
- 保存实际环境、来源、结果与证据；真实 GitHub 发布、自动安装替换或未实测平台不能冒充已通过。此任务本身不授权正式发布或安装到用户日常使用位置。

规格用户故事：65 及全部任务的组合验收；依赖的 01、03 已通过其他依赖传递覆盖，不重复列为直接阻塞。

## 依赖检查与并行范围

1. 首先完成 01。
2. 01 完成后，02、03、05–10 在依赖关系上均可推进；实际并行数量受执行资源限制。
3. 03 完成后可以推进 04，不必等待全部正文。
4. 02、04、05–10 完成后推进 11。

这些是行为依赖，不是文件占用依赖。多个内容任务可能改同一个登记入口或设置页面，应在集成时协调合并；不能因此把本可独立的业务流程排成长串，也不能互相覆盖。

26 组覆盖归属：01 → 21；05 → 01、02、12、13、14；06 → 03、04、05、07；07 → 06、08、09、10、11；08 → 15、16、17；09 → 18、19、20、22；10 → 23、24、25、26。没有漏组或重复主责，组 21 被其他任务引用仍由 01 主责。
