# 配置驱动的操作指引与发布编写流程

Status: ready-for-agent

日期：2026-10-21。类型：功能实施规格。需求来源：已完成的 Q1–Q20 设计确认；测试边界沿用 Q19，并由 Q20 随完整方案确认。本状态表示可以进入任务拆分及实施，不表示功能或首批指引正文已经完成。

## Problem Statement

Clever Workbench 已包含台账、任务、文档、资料保护、备份恢复、更新及工具等多种流程，使用者目前需要自行寻找入口和摸索操作。功能附近没有统一的使用指引，设置中也没有集中查阅入口；首次接触功能、升级后遇到操作变化或需要恢复失败操作时，用户难以快速确认准备条件、具体步骤和完成结果。

维护者目前依据提交记录生成 GitHub 发布正文，缺少持续维护的用户操作说明及与应用版本一致的内容来源。提交标题无法可靠解释如何使用功能，也无法区分“本次没有操作变化”和“尚未编写说明”。发布失败后改用新版本号，还可能造成指引、实际源码和安装包版本不对应。

用户希望首批覆盖全部现有功能，之后每次发布都按统一规范编写操作说明；内容能够通过配置展示、随安装包离线使用。提醒要低干扰，指引缺项只应产生明确警告，不得新增发布阻断或影响正常业务使用。

## Solution

提供功能操作指引和版本操作指引两类内容：功能操作指引持续说明当前功能如何使用；版本操作指引介绍本次升级范围内的操作变化，并复用相应功能指引。维护者以 JSON 和仓库内图片编写，应用提供统一图文步骤弹窗、功能附近的手动入口及设置中的集中查阅入口。

首批按 26 组现有用户流程完成实际内容覆盖，并补充指引功能自身的使用说明；复杂流程可以拆分，共用步骤可以复用，但不能用若干空标题或三篇示例替代全量覆盖。普通功能指引由用户手动打开；自动弹窗只汇总升级变化，不连续弹出所有教程。

升级后的提示只在界面就绪、编辑保存完成且没有其他弹窗或安装／恢复流程时出现。实际成功显示后记录为该设备已提示，关闭、Esc 或重启不重复；用户仍可手动重看。跨版本升级合并期间的变化，首次启用只考虑当前版本；设备提示记录不随业务备份恢复。

每次发布前编写待发布操作说明并核对，发布准备时绑定实际版本和源码。应用内完整步骤和 GitHub 用户摘要从同一内容源生成，保留技术提交明细。缺失内容、无效引用及核对缺项在本地和 GitHub Actions 中统一警告，并在应用中降级；此策略不改变既有源码身份、构建、测试和安装包安全校验要求。

## User Stories

1. 作为工作台使用者，我希望在当前功能附近打开“使用指引”，以便不离开当前工作背景就能了解操作方法。
2. 作为工作台使用者，我希望在设置中集中查阅所有功能指引，以便不知道入口时也能找到帮助。
3. 作为离线使用者，我希望文字、必要图片和随包版本历史在断网时仍可阅读，以便核心帮助不依赖网络。
4. 作为首次使用某项功能的人，我希望看到用途、准备条件、入口、步骤、完成结果和常见问题，以便判断是否适用并独立完成操作。
5. 作为按步骤操作的使用者，我希望每一步都有一个明确动作和可观察结果，以便知道当前是否做对以及下一步是什么。
6. 作为查看复杂流程的使用者，我希望能够前后切换步骤、了解当前位置并随时关闭，以便按自己的节奏学习。
7. 作为键盘使用者，我希望通过 Esc 关闭弹窗并回到原来的焦点，以便阅读指引不会打断键盘操作。
8. 作为使用窄窗口或长说明的人，我希望内容可滚动且主要操作始终可到达，以便关闭和前往功能不被挤出界面。
9. 作为有外观或可访问性偏好的人，我希望指引遵守主题、减少透明度、增强对比和减少动态效果设置，以便长时间阅读仍然舒适。
10. 作为阅读指引的使用者，我希望“前往功能”只带我进入正确位置，以便导出、删除、恢复、解锁和安装仍由我明确操作。
11. 作为正在编辑的人，我希望跳转前完成必要保存，保存失败时保留输入和当前位置，以便不会因查阅帮助丢失工作。
12. 作为尚未选择系统或对象的人，我希望指引带我到合适的选择入口，以便不会错误地使用过期或随意选定的背景。
13. 作为正在输入或处理弹窗的人，我希望版本提示等待合适时机，以便不会抢走焦点或覆盖正在进行的流程。
14. 作为首次启用指引的人，我希望只看到当前版本的相关变化，以便不会被全部历史说明淹没。
15. 作为升级用户，我希望操作有变化时自动看到一次版本说明，以便知道升级后需要如何使用。
16. 作为跨多个版本升级的用户，我希望一次查看期间相关变化并合并同一功能的介绍，以便不遗漏变化也不连续处理多个弹窗。
17. 作为升级目标版本本身没有新操作的用户，我希望中间版本的操作变化仍能被提示，以便跳过版本不会丢失必要说明。
18. 作为整个升级范围都没有操作变化的用户，我希望应用安静启动，以便普通修复不会带来无意义的教程。
19. 作为已经看到版本指引的用户，我希望关闭、Esc、重启或降级后再次升级都不重复提示同一版本，以便提示保持克制。
20. 作为后来需要复习的用户，我希望随时手动重看功能与版本说明，以便一次提示不会限制后续查阅。
21. 作为恢复旧业务备份的用户，我希望本机已提示记录不回退，以便恢复资料不会重复弹出旧提醒。
22. 作为换设备的用户，我希望新设备按首次启用处理，以便不会把其他设备的提示历史误当作本机行为。
23. 作为用户，我希望“已提示”只表示显示过说明，以便产品不会声称我已经读完、学会或完成操作。
24. 作为查看历史说明的人，我希望历史摘要保持当时的内容，而操作入口使用当前有效位置，以便既能追溯又不会进入已移除的功能。
25. 作为遇到缺图或无效指引的用户，我希望看到可用文字或简短不可用说明，以便帮助内容的问题不会导致应用崩溃或空弹窗。
26. 作为工作台使用者，我希望了解首页待办、文档入口、常用对象整理及基本窗口操作，以便快速开始并安排日常工作。
27. 作为查找或录入资料的人，我希望了解全局搜索、结果快捷操作、九种新建项和背景继承，以便减少反复定位与选择。
28. 作为维护系统资料的人，我希望了解系统、环境、项目档案和项目沿革的操作及关系，以便不把项目变化误认为系统身份变化。
29. 作为浏览台账的人，我希望了解分类、搜索、范围筛选、列表与详情切换及单条和多条复制，以便快速找到并安全分享所需资料。
30. 作为维护访问入口的人，我希望了解多地址、常用地址、账号关联、跨系统复制和删除影响，以便准确维护入口资料。
31. 作为维护服务器和数据库／中间件的人，我希望了解字段编辑、附加字段、账号关联、复制及删除限制，以便逐步补齐资源资料。
32. 作为管理账号的人，我希望了解归属、秘密显示与隐藏、不同复制方式、收藏和归属调整，以便准确使用账号并保护秘密。
33. 作为记录应用部署的人，我希望了解服务、部署节点、环境、服务器及固定／按需运行方式，以便正确描述部署关系。
34. 作为维护运行资料的人，我希望了解运行作业、备份策略及相关任务和文档入口，以便将运维记录与个人工作分别管理。
35. 作为批量录入资料的人，我希望了解表格粘贴、字段映射、逐行校对、提交及丢弃，以便避免错误批量新增。
36. 作为交接系统资料的人，我希望了解导出格式、内容范围、秘密选择和输出结果，以便知道资料包适合阅读交接而不用于恢复。
37. 作为管理工作任务的人，我希望了解草稿、保存、计划时间、标签、筛选、批量归属、完成及重开，以便按自己的流程推进工作。
38. 作为编写技术文档的人，我希望了解文档归属、编辑模式、表格代码、本地图片、保存及失败重试，以便持续记录方案并复用编辑能力。
39. 作为查看工作回顾的人，我希望了解月份、系统视图和日历跨度的含义，以便不将任务跨度误读为实际工时。
40. 作为处理删除记录的人，我希望了解任务和文档各自的回收站、恢复及永久删除边界，以便知道哪些操作仍可撤回。
41. 作为调整工作环境的人，我希望了解主题和可访问性选项，以便获得适合自己的界面。
42. 作为保护凭据的人，我希望了解默认系统保护及可选主密码的启用、解锁、锁定、更改和关闭，以便正确管理日常秘密访问。
43. 作为管理备份的人，我希望了解独立备份密码的设置、更改及历史密码规则，以便知道恢复每份备份时需要什么密码。
44. 作为需要资料保障的人，我希望了解手动和自动完整备份、目录、结果、重试及保留范围，以便确认资料确实被备份。
45. 作为恢复或迁移资料的人，我希望了解预检、密码、摘要确认、整份替换和恢复前副本，以便理解恢复影响和失败后的处理方法。
46. 作为升级应用的人，我希望了解检查、下载、立即或稍后重启、保存备份与安装位置要求，以便区分下载完成和安装成功。
47. 作为遇到更新失败的人，我希望了解历史、日志、备份与旧应用定位及系统授权处理，以便选择正确恢复步骤而不误认为已自动回滚。
48. 作为归档文件的人，我希望了解文件／目录选择、输出、分片、密码和结果，以便生成能正确还原的文本归档。
49. 作为按 Git 记录选择文件的人，我希望了解提交筛选的是路径而实际读取当前磁盘内容，以便不把该工具误认为导出历史快照。
50. 作为从目录还原归档的人，我希望了解完整分片、原密码和输出位置要求，以便安全还原且不覆盖已有资料。
51. 作为从剪贴板还原归档的人，我希望了解分片收集、重复和异常处理、完整性与后台执行，以便完成跨渠道传递后的还原。
52. 作为首次使用指引功能的人，我希望知道如何打开功能指引和重看版本说明，以便帮助入口本身也容易理解。
53. 作为维护者，我希望以统一 JSON 模板和本地图片配置内容、入口及展示条件，以便新增指引不需要复制一套弹窗代码。
54. 作为维护者，我希望功能指引具有稳定标识、内容修订和平台范围，以便版本引用不会因显示名称变化而失效。
55. 作为维护者，我希望复用功能内容并保留已发布版本摘要，以便当前用法和历史变化可以同时维护。
56. 作为维护者，我希望每次发布明确声明操作变化或无新增操作的原因，以便缺少说明不会被误认为没有变化。
57. 作为维护者，我希望先编写待发布说明，再绑定实际版本与源码，以便失败后换版本号时仍能正确使用已核对内容。
58. 作为维护者，我希望同一来源生成应用内容和 GitHub 摘要，并保留完整提交清单，以便用户说明和技术追溯保持一致。
59. 作为维护者，我希望本地和 CI 都列出具体文件、字段、问题及修正建议，以便一次看清缺失和无效内容。
60. 作为维护者，我希望指引内容问题只警告且不阻断后续生成、打包或发布，以便保留已确认的发布策略。
61. 作为维护者，我希望既有构建、身份与安装包安全检查继续有效，以便内容警告策略不会掩盖其他故障。
62. 作为核对指引的人，我希望记录真实源码、环境、步骤、图片和结果及缺项，以便能够区分通过、失败、未验证和不适用。
63. 作为维护者，我希望发布只使用计划远端源码中的指引与图片，以便本地未提交内容不会意外进入安装包。
64. 作为处理失败发布的人，我希望重跑固定 tag 时保持内容来源不变，以便不会混入后来修改的待发布说明。
65. 作为维护者，我希望首批覆盖清单逐项关联实际指引步骤和核对证据，以便展示机制完成后仍能看清哪些正文尚未交付。

## Implementation Decisions

### 1. 内容模型和责任边界

- 沿用已确认领域术语及 ADR 0012；功能操作指引、待发布操作说明、版本操作指引、指引提示记录分别承担当前用法、发布准备、版本变化和设备去重职责。
- 内容使用版本化 JSON，功能与步骤有稳定标识，内容修订不改变功能身份；支持用途、准备条件、入口、步骤、完成结果、常见问题、必要图片、平台范围和预设展示位置。
- 准备条件或常见问题确实不适用时记录原因；占位文字、空缺字段和无说明的空内容不算完成。模板是编写工具，不能作为实际内容进入安装包。
- 待发布说明显式区分有操作变化与无新增操作。缺文件、损坏或未编写属于未知状态，不得转成无新增操作；是否影响操作由维护者核对，机器只检查已列变更的结构与关联。
- 已发布版本摘要保留不变。功能指引随新版本修订，当前应用默认展示当前有效用法；历史摘要链接当前有效功能，已移除入口明确不可用，旧完整内容可从对应版本源码追溯。

### 2. 配置解释与离线分发

- 将内容读取、格式检查、引用解析、版本汇总和警告报告收敛为共享能力，供应用加载与发布生成复用；不为每个页面分别实现内容解释规则。
- 输入是受控配置和资源，输出是可展示内容、可用入口、版本摘要及结构化问题报告。功能导航和展示位置引用明确登记的标识，不把任意地址、脚本、HTML、文件打开命令或可执行表达式作为配置能力。
- 运行时校验是必须的，类型声明不能代替实际文件检查。单项异常独立降级；重复标识不能随机选一个，未知格式不能猜测执行。
- 应用内容、版本历史与所需图片随同版本打包，不依赖网络或开发机文件。图片访问限定在对应受控资源内，越界、非法引用及不可用图片不读取；文字步骤保留可读性。
- 内容解析与构建分离，避免将损坏 JSON 作为强制静态源码导入导致构建失败。发布侧和运行侧都能在部分内容无效时继续处理其他有效内容。

### 3. 应用集成与受控入口

- 设置增加统一查阅入口，业务功能附近提供“使用指引”；密集区域可沿用现有菜单，使用一致文案及可访问名称。入口登记反映真实可用功能和当前平台，不为每个按钮重复放置教程入口。
- 使用共享图文步骤弹窗，支持步骤位置、前后切换、关闭和前往功能。关闭及主要操作在长内容、窄窗口中保持可达。
- 复用共享对话框、语义主题与焦点行为；保留原生无拖拽区域。键盘、深浅主题及辅助外观设置与其他页面一致。
- “前往功能”复用现有模块导航、对象背景和保存协调；没有适用对象时进入明确的选择入口，背景失效时不继续使用旧对象。
- 导航只改变查看位置，不隐式创建、删除、导出、恢复、解锁或安装。保存失败保留编辑与当前位置并允许重试；资料代次变化、恢复切换及安装冻结不能被指引绕过。
- 新增设备记录能力经类型化桌面接口和受控 IPC 访问；主进程负责来源、主 frame、参数、代次和操作时机校验，渲染层不直接读写文件。

### 4. 提示计划与状态

- 首次没有有效记录时仅考虑当前版本，不回放全部历史。后续升级在当前版本范围内汇总尚待提示的变化，按功能合并并使用当前有效指引；合并保留不同操作变化的含义，不能仅以最后一条覆盖之前所有变化。
- 判断是否需要提示时考虑整个升级范围。即使目标版本明确无新增操作，中间版本仍有变化也须汇总；整个范围都明确无变化则安静处理。
- 待提示与已启动、已提示分别管理。发现新版本、生成计划或等待界面都不能视为已提示；只有弹窗实际成功显示，才确认该次覆盖的版本。
- 正常记录成功后，关闭、Esc、重启及降级后重新升级不重复同一版本；手动查阅不重置去重状态，也不被去重状态阻止。等待期间关闭应用不能导致尚未显示的说明被消耗。
- 自动提示须等待主界面及当前页面就绪、持续输入结束、必要保存完成、没有其他弹窗和阻断流程。可展示条件检查与打开过程协调，避免其他弹窗抢先出现时重叠；不强制关闭已有弹窗，不通过持续抢焦点推进教程。
- 指引与更新重启、密码、备份恢复等弹窗明确避让。因恢复而变化的旧页面和迟到请求不能继续导航或覆盖当前提示状态。
- 历史缺口只声明已知记录范围，不能编造缺失版本的变化，也不能宣称该范围全部无变化。无有效内容不自动弹空窗口，手动查看给出简短不可用说明。

### 5. 设备记录与资料保护

- 提示记录由主进程持有，使用与业务数据库、资料代次和加密备份独立的设备状态。恢复业务备份不回退记录，换设备按首次启用处理。
- 复用现有应用资料目录隔离能力，设备记录同样受测试隔离约束；独立于业务备份不意味着可以写入测试目录之外的真实设备状态。
- 持久化采用可恢复写入方式，保存失败不返回成功。本次进程内不因持续重试而反复弹出；跨重启无法保证持久去重时如实保留故障，不声称已成功记忆。损坏记录采用首次启用规则，不回放全部历史。
- 提示记录不包含业务秘密、学习进度或操作完成情况；不改变业务数据库模型和备份格式，也不把功能阅读情况写入业务快照。

### 6. 首批完整内容交付

首批必须交付下列 26 组的实际操作正文，并补充指引功能自身说明。每组可按短子流程组织，关联共享指引；详细覆盖清单是验收依据，组数和文件数本身不是完成依据。

| 组 | 必须覆盖的流程 |

| 01 工作台基础 | 首页待办、完成撤销、文档入口、常用系统／入口／账号／工具的选择排序移除、模块与原生窗口菜单、保存反馈。 |
| 02 搜索与新建 | 全局搜索及结果操作、键盘使用、九种新建项、系统／环境背景、取消和先保存。 |
| 03 系统、环境与项目 | 系统基本信息、环境增改删、当前项目与沿革、项目增改、归档恢复和删除空项目。 |

| 23 文件归档 | 文件／目录选择、输出、分片大小、密码、进度、结果和已有目录保护。 |

- 正文使用实际界面文案、当前领域术语和隔离示例资料；图片按需制作，不是每步必配，也不能用真实业务资料充当示例。
- 新备份依 ADR 0011 使用独立备份密码；历史备份依其格式使用生成时密码。主密码、备份密码、ZIP 归档密码分别说明，正式交付同步校正过时的根规范及相关使用文档口径。
- 内容与最终实施源码绑定。当前本地与已知远端的导出内容选择、任务开始日期筛选及输出形态不同；合入的功能必须覆盖，未包含的控件不得写成当前存在。
- 只把实际能恢复的对象写为可恢复；任务和文档回收站不被描述为所有台账实体的通用回收站。工作回顾不称为实际工时，下载完成不称为安装成功，人工安装不称为无人值守升级成功。

### 7. 发布准备、绑定和同源生成

- 每次发布先列出用户操作变化、更新关联功能指引并填写待发布说明；没有操作变化也提供明确原因。核对记录包含实际核对人、时间、源码、环境、对应步骤、结果、证据与缺项。
- 发布仍使用已提交到计划远端分支的源码及内容，忽略本地未提交、未跟踪或未推送资料。只读预览展示拟发布内容及警告，不创建提交、tag 或发布记录，不改当前工作区。
- 正式准备时将说明绑定实际版本、tag 与业务源码，和应用版本变更作为同一发布准备结果，保留原核对来源。构建另记录 tag 对应的版本提交 SHA，不把提交自己的 SHA 写回同一提交。
- 当前版本准备只修改包版本字段的约束需要扩展为明确包含本次版本记录；允许的变更范围仍受控，不能把新能力当作任意暂存其他文件的理由。
- 失败占用版本号后可重新规划并绑定新版本。源码或内容改变时重新核对差异；固定 tag 的重跑只读取该 tag 内容，不读取后来编辑的待发布说明。失败、草稿和未实际发布版本不能被自动当作用户已经升级经过的正式版本；无法确定发布历史时保留缺口说明。
- 应用完整内容和 GitHub 用户摘要由同一绑定数据产生。正文提供用户摘要、操作说明或应用内查阅路径，保留完整技术提交清单和来源信息；需要仓库链接时固定到对应版本，并遵守私有仓库访问权限。
- 对缺失指引如实说明“暂未提供完整操作指引”，保留可用部分；不把缺失内容自动生成为“无新增操作”。发布后不覆盖已公开 tag、摘要或资产，后续修订通过新版本交付。

### 8. 仅警告的校验与异常隔离

- 本地发布与 GitHub Actions 使用同一内容规则并汇总问题，至少包含警告代码、文件／字段、问题与修正办法；一次收集多项，不在首个缺项时直接中止。
- 校验覆盖缺文件、格式、必填项、占位内容、重复标识、无效引用、入口、图片路径、已声明操作变化的关联覆盖及核对记录缺项；不宣称自动证明所有用户可见变化都已被人工列出。
- 无效内容安全降级：跳过不能确定的条目；缺图保留文字；失效入口停止跳转并说明；没有有效版本内容则不弹空窗口；手动入口仍有可理解反馈。
- 内容缺项不新增发布确认，不以错误退出阻断，也不能在正文生成、资源整理、构建或安装包检查阶段换一种方式阻断同一问题。实际内容质量报告必须保留，发布成功不等于缺项消失或首批内容全部完成。
- 既有 Git 身份、来源、版本一致性、代码构建、行为测试、原生包及远程资产校验继续执行。仅对指引内容问题容错，不用通用忽略错误掩盖实现缺陷或包安全失败。

### 9. 交付边界

- 功能机制、首批内容、发布集成分别有完成证据。必须在实际运行入口验证内容与操作相符，不能只证明 JSON 可解析或能打开一个演示弹窗。
- 所有源码提交继续使用当前生效的本地 Git author 与 committer，提交标题和正文用中文；缺失或冲突按仓库规则处理，不以配置中的审核人替代 Git 身份。
- 开发、打包、真实网络、安装替换与健康启动的结果分别记录；本规格不以指引测试替代原更新器的真实升级验收，也不擅自执行推送或正式发布。

## Testing Decisions

### 已确认的最高测试边界

用户在 Q19 接受 macOS 安装版为主的验收边界，并在 Q20 确认完整方案。本规格沿用该选择，不增加新的产品访谈或更低层的逐函数测试要求。

| 边界 | 主要验证对象 | 复用依据与方法 |
| --- | --- | --- |
| 安装版 Electron 的页面与受控桌面接口 | 查阅、导航、提示计划与记录、保存、弹窗避让、恢复及离线资源 | 现有桌面启动封装可切换开发输出与安装版，已有更新弹窗关闭和重启提示、备份恢复代次、统一外观与窄窗口用例。通过真实界面及公开桌面能力设置隔离场景，断言用户可见结果。 |
| 现有发布编排入口及产物 | 远端内容选择、预览、版本绑定、警告、同源摘要、失败重试和最终打包输入 | 现有发布测试使用临时 Git 远端、独立工作区和 GitHub 响应替身，已验证远端专用源码、本地身份、失败重跑及资产发布。扩展这些外部行为用例，不建立一套重复的底层私有实现测试。 |

桌面与发布是两个不同的用户入口，保留这两个高层边界有实际必要。共享配置和汇总能力只在高层难以稳定覆盖的解析、排序及故障组合上补充少量契约测试，围绕公开输入输出，不验证内部函数调用次数或私有状态布局。

### 必须覆盖的行为

1. **手动查阅与离线资源**：功能附近及设置入口能打开同一有效指引；前后步骤、图片替代文字、前往功能、关闭重开和历史摘要有效；断网及离开开发目录后仍能读取安装包自身内容。
2. **提示生命周期**：首启仅当前、连续升级、跨版本合并、目标无变化但中间有变化、全范围无变化、历史缺口、未公开版本、等待期间退出、成功显示后关闭／Esc／重启、手动重看及降级再升级。
3. **设备持久化**：同设备重启去重；恢复更早的业务备份不回退提示记录；新设备按首次规则；记录损坏和写入失败不伪报成功，不形成当前会话反复弹窗。检查完整备份不携带设备提示状态。
4. **保存与避让**：持续输入、待保存、保存失败、现有密码／更新重启／备份弹窗、安装冻结、恢复切换及迟到响应。断言输入保留、其他流程继续、没有重叠抢焦点，必要时机解除后才提示。
5. **导航副作用边界**：无对象背景进入选择流程，旧背景失效不误跳；前往功能不会自动执行创建、删除、导出、解锁、恢复或更新，也不能绕过当前安全限制。
6. **内容异常**：单篇损坏不影响其他条目和应用启动；缺图、占位内容、未知格式、重复标识、非法路径、缺引用和已移除功能能够降级；没有有效版本内容时无自动空弹窗。
7. **视觉与原生交互**：浅色、深色及跟随系统、辅助外观设置、正常／窄窗口、长标题与长步骤、键盘焦点、Esc 和焦点返回；实际原生鼠标点击关闭并检查无拖拽区域，不能只用浏览器自动点击认定原生问题已解决。
8. **远端专用来源与预览**：本地不同或未提交的指引不进入发布；预览输出实际远端内容和警告且不改变工作区；版本准备只加入允许的版本及指引记录，保留本地身份和中文提交要求。
9. **绑定和重跑**：实际版本、业务源码、版本提交、应用内内容与 GitHub 摘要一致；占用版本后重新绑定、固定 tag 重跑、核对后源码变化、历史发布缺口和草稿失败状态均不混用内容。
10. **非阻断链路**：从缺失／损坏内容输入开始，经过检查、正文生成、资源整理及打包仍能产生允许发布的降级结果，并保留警告；本地和 CI 汇总语义一致。反例中真正的构建或原生包安全失败仍失败。
11. **全量正文**：26 组清单每项映射到有效指引及步骤，逐项记录入口、前置条件、操作结果、截图和取消／失败路径的核对证据。检查实际选定源码包含的变化，不以文件数、标题数或截图快照替代内容核验。

### 测试数据、准确性与范围控制

- 使用现有隔离应用资料目录，确认设备记录、数据库、图片和备份均留在测试环境；不读取、恢复或清理真实用户资料。模拟换设备时使用另一份隔离环境。
- 提示生命周期可以使用受控版本与内容夹具验证；打包资源与真实原生边界需安装版验证。使用夹具不被描述为真实 GitHub 升级或实际安装替换已经通过。
- 复用已有保存失败、迟到文件选择、更新状态及原生对话框替身，在外部适配边界制造故障；不为了测试向生产配置加入任意脚本、任意磁盘访问或绕过授权的入口。
- 发布行为测试继续使用独立临时仓库和可控远程响应；不得为了证明警告非阻断而向真实仓库发布损坏版本。实际 CI 运行、真实远程资产和安装结果只有执行后才能分别记为通过。
- 对实际仓库内容的完整性输出警告及核对报告；发布流水线中的行为测试使用明确夹具验证机制，不以“当前所有内容必须有效”的断言重新引入内容阻断。首批内容是否达到本规格完成条件单独记录，不能因发布允许继续就标为完成。
- 稳定的纯逻辑测试只覆盖外部契约和关键边界；不为文档链接或可逆样式变化建立镜像实现的测试。完成必要验证后仅因新增变更、失败或尚未消除的疑点扩大回归。
- 验收报告区分通过、失败、未验证和不适用，记录环境及原因。现有底层功能的原有失败结论不因新增指引或修改文档而自动变成通过。

## Out of Scope

- 无需发布新版本即可远程修改指引的服务、在线配置平台和远程图片依赖。
- 应用内编写或编辑指引、任意 HTML 或脚本、逐控件高亮导览、模拟用户自动执行业务操作。
- 阅读完成率、学习追踪、强制阅读、跨设备同步提示状态、将提示记录加入业务备份。
- 因指引缺项阻止发布、强制二次确认、自动推断全部源码变化或把缺失说明当作无新增操作。
- 重写历史发布内容、自动补造全部旧版本指引、覆盖已公开标签或资产。
- 引入新的业务归属规则、修改数据库／备份格式、改造加密算法、扩展现有更新器平台支持。
- 将 Windows、Intel 或任何未实测平台写为已经完成安装与自动更新验收。
- 改变现有工具、任务、台账、删除和恢复语义，或将发现的菜单文案差异扩大为无关重构。需要更正的使用说明应以实际行为为准。
