4. **准备维护者核对。** 由代理整理逐项步骤、截图、入口、通过／失败／未验证和源码证据，保留机器检查警告；用户检查实际操作与图片后对拟发布源码作最后人工签认。仅在真实签认后填写审核人、时间与结果，不把缺失项自动改写成“无新增操作”。
5. **合并、推送与正式发布。** 用户确认最终界面及核对记录后，在干净工作区审查合入主分支，按本地 `ikuku-tt` Git 身份与中文 commit 规则提交、核验并推送。发布入口按当时最新远端 Release 与 tag 选择实际新版本，绑定该次源码和操作说明；GitHub Actions 的构建、安全与资产检查保持有效，指引内容问题按已确认规则只警告。
