# macOS 双击发布实施记录

日期：2026-10-20。

## 实现

- 根目录 `发布新版本.command` 使用 macOS Terminal，补充 Homebrew PATH，按自身位置定位项目，结束后等待回车；脚本设置为可执行文件。
- `scripts/publish-release.mjs` 提供交互和只读预览；`scripts/release-tools/` 分离版本／说明、GitHub 受控传输、远端快照及发布协调。
- 只读取远端 master；临时仓库保留完整历史。未提交、未跟踪和未推送的本地业务内容不纳入，版本准备只修改两个版本文件。author／committer 与本地 Git 配置一致，中文提交说明在提交后再次核验。
- 版本提交和注释 tag 通过 Git 原子推送提交，避免只更新 master 或只创建 tag。计划确认期间再次核对远端 HEAD 和最新 Release，变化时停止并重新规划。
- 未完成版本通过版本提交中的源码关联信息恢复；仓库本地锁、云端活动任务检查和仓库级 Actions 并发组避免重复发布。恢复时使用既有 tag，失败任务通过 Actions rerun 继续；没有对应任务时可针对同一 tag 重新触发。
- 原有 tag 发布工作流扩展为全历史检出、可重试调用、DMG 完整性验证和专用草稿发布入口。本轮仅 macOS arm64；现有其他桌面 CI 的 Windows 检查未被用作 macOS 发布门槛。
- 云端逐一核对 ZIP、DMG、SHA256SUMS 的大小与 GitHub SHA-256，再下载校验文件比对，完成后才公开 latest。只替换尚未公开草稿中的本次资产；正式版本拒绝覆盖。
- 凭据仅在内存及 curl stdin，GitHub API 重定向后的资产 CDN 请求不携带授权；代理从本机配置发现，无硬编码代理。
- 两项列表与详情同时展示的回归显式设定 1380px 视口，保留 1024px 窄窗口测试。

## 验证

- 隔离 Git 仓库与模拟 GitHub API 覆盖预览、无新提交、取消、远端变化、原子推送后的源码内容、中文作者署名、两文件版本提交、恢复同一源码、并发保护、草稿续传、摘要篡改和 CDN 授权边界。版本文件符号链接也必须拒绝，防止离开隔离目录写入。
- 最终单元测试 29 个文件通过，146 项通过、3 项条件跳过；类型检查和生产构建通过。原生安装版相关回归 4 项通过。
- 从 `/tmp` 执行实际 `发布新版本.command --dry-run` 成功定位原仓库，真实 API 返回最新 v0.1.4，列出远端 6dde1c9 文档提交，并核对本地署名 ikuku-tt；没有创建真实版本提交、tag、草稿或发布任务。
- Bash 语法、Node 入口语法、发布工作流 YAML 结构和本次改动的格式／diff 检查通过。

## 验证边界

本轮不通过创建新正式版本来验证脚本。真实 GitHub 写入、云端构建后公开 Release 的完整链路留待维护者实际启动；隔离 Git／API 验证不冒充真实云端发布成功。UI 回归使用已有最终 v0.1.4 安装版及隔离资料，应用业务代码未因本轮脚本改变，也未替换用户应用。

原工作区的 `AGENTS.md` 为用户已有的项目规范改动，不混入本次发布脚本提交。
