## 已确认范围

用户通过 grilling 确认实施：根目录提供 `发布新版本.command`，只取远端 `origin/master` 已推送的源码；比较最新正式 Release tag 后的全部提交，包含文档。无新提交则退出。默认递增补丁号，允许指定更高版本，遇到被占用的版本保留原 tag；同一源码的未完成版本可重试。

脚本在隔离目录修改应用与锁文件版本，以本地 Git 配置的真实账号创建中文版本提交，原子推送 master 与注释 tag。只发布 macOS arm64 ZIP、DMG、SHA256SUMS；GitHub Actions 负责构建、单元测试、真实包检查、原生解压／传输和安装版桌面回归，全部通过且远程资产校验一致后发布 latest。

终端预览源码、提交、版本与平台，确认一次后自动执行到完成。当前目录未提交或未推送的业务修改不纳入发布。失败保留日志、已推送 tag 和草稿，重跑可恢复同一源码；源码变化后重新规划，不覆盖公开版本。仓库本地锁与云端发布并发组防止重复发布；已有任务运行时提供链接并提示等待。

## 验收

- 实际入口可执行，按文件自身位置找到项目；检查 Node、Git、本地身份与 GitHub 授权，凭据不写入命令行、日志或磁盘。
- 远端快照的测试证明未提交文件和未推送提交不入包；版本提交只改两个版本文件且 author／committer 均为本地用户。
- 验证无变更、取消、预览、版本冲突、远端变化、已有任务、锁、失败重试与云端发布成功／失败分支。
- 草稿上传校验名称、大小、SHA-256，下载远程校验清单核对；中途失败不公开，已公开版本拒绝修改。
- 两项依赖列表与详情同时展示的回归显式使用宽视口，保留已有 1024px 窄窗口导航回归。
- 不为验证脚本而创建真实正式版本或替换用户应用。真实远端只进行读取预览；完整远端写入路径用隔离 Git 仓库和模拟 GitHub API 验证，未执行的云端运行如实记录。
