## 源项目核查

来源目录：`/Users/axelton/code/zip-to-txt-transfrom`。以下是现有行为，迁移范围和需要改变的规则由访谈确认。

| 能力 | 现有行为 |
| --- | --- |
| 完整归档 | 单个文件或目录，保留顶层名称、二进制、空文件与空目录；普通目录归档包含隐藏文件，不应用 `.gitignore` |
| 加密分片 | 密码加密后编码为 Base64 文本；每片上限 1～200 MB，十进制，默认 50 MB；文件名为 `part-000001.txt` 等 |
| 目录还原 | 校验片名、顺序、完整性、归档身份和密码后还原；多余 TXT、缺片、混包及损坏均报错 |
| 剪贴板还原 | 一次读取一个完整分片，可乱序加入、删除和替换；仅显示元信息及短预览，失败保留本次分片供重试 |
| Git 文件筛选 | 选择本地或已有远程跟踪分支，按作者和时间筛选提交，多选后预览去重路径及缺失项；只读取本地历史 |
| Git 内容来源 | 提交只确定路径，归档读取当前磁盘内容；缺失文件跳过，不输出删除指令，不检出历史版本 |
| 输出保护 | 目标目录已存在则拒绝；失败清理本次输出；拒绝路径穿越、符号链接及跨平台文件名冲突 |
| 偏好和密码 | 记忆上次源目录、输出目录、分片大小；密码不持久化，任务完成或失败后清除 |
| 运行交互 | 展示各阶段真实进度，完成后可打开目录或复制路径；原程序运行时禁止关闭，无取消、队列或历史记录 |

格式为 `ZTXT1`，使用 scrypt 派生密钥、AES-256-GCM 分片认证和 Base64 编码。原仓库已有双向互通测试。磁盘分片和粘贴文本的空白兼容规则不同，迁移时需覆盖。

核查依据：源项目 `zip_to_txt.py`、`git_archive.py`、`paste_restore.py`、`zip_to_txt_gui.py`、`packaging/test_compatibility.py` 及 `docs/adr/`。这些事实来自静态阅读，尚未运行迁移后的兼容或性能验证。

## 工作台接入依据

- `src/app/modules.tsx` 已集中登记一级导航、页面、搜索类型和快捷新建动作；工具菜单可沿用此机制。
- `src/features/home/HomePage.tsx` 与 `FavoriteButton.tsx` 已提供常用项选择、排序、移除和设为常用。
- `src/home-types.ts`、`electron/favorites.ts` 当前只支持系统、账号和访问入口；工具接入需同步扩展类型、有效性检查及备份校验，不能只增加首页按钮。
- `electron/store.ts` 将有序常用项保存到 SQLite 偏好中；无默认固定项。完整备份恢复已有覆盖。
- 主窗口启用隔离与沙箱，文件选择、文件处理和 IPC 校验沿用 `electron/main.ts`、`electron/preload.ts` 的边界。
- 当前页面切换会重建页面状态；尚无工具运行生命周期管理。大文本和长任务不适合直接留在页面局部状态或通过 IPC 全文搬运。
- 工作台已具备 ZIP 读写依赖；源项目核心依赖 Python 和 cryptography，Git 功能另依赖本机 Git。最终实现方式应保障现有 macOS／Windows 桌面交付约定。

## 已确认决定

1. 工具面向整个工作台使用，无需先选择系统或项目。
2. 后续工具以开发者新增内置模块的方式接入，统一登记并随工作台版本发布。
3. 首页以快捷卡片打开工具完整页面，复用现有常用入口的选择、排序、移除、持久化和完整备份能力。
4. 首版完整迁移完整归档、Git 文件筛选归档、分片目录还原、剪贴板分片还原四项能力。
5. 沿用现有归档格式，工作台与原独立工具生成的文本分片可以双向还原，见 `docs/adr/0009-preserve-zip-text-archive-compatibility.md`。
6. 归档和还原在切换页面后继续运行，返回工具页可查看当前进度和结果。
7. Git 提交用于确定文件路径，实际归档读取当前磁盘内容；界面明确说明会包含这些文件的未提交修改，不将操作描述为导出历史快照。
8. 工具仍在处理任务时，关闭窗口或退出应用需提示尚未完成并保持运行；结束后才允许正常退出。

## 完整规格的补充规则

以下规则延续原工具及工作台已有行为，与上述选择共同进行最终确认。

### 工具目录与首页

- 侧栏新增“工具”，显示工具名称、用途及打开入口；首个工具命名为“ZIP 文本归档”。
- 每个工具有稳定标识、名称、用途说明、图标和页面入口；工具目录与首页使用同一登记信息，新增工具无需分别向两处填入展示逻辑。
- 用户可在工具入口设为常用，也可从首页常用入口选择器添加；工具与现有常用项共同排序，移除常用项不删除工具。
- 不自动将首个工具固定到首页，不自动扫描用户文件或运行工具。常用设置随现有完整备份迁移。

### ZIP 操作与数据

- 延续上表记录的文件范围、顶层目录、隐藏文件、空目录、分片命名、1～200 MB 上限和默认 50 MB 等行为。
- 延续原工具的默认输出位置，并允许选择输出目录；输出目录已存在时拒绝覆盖，失败时清理本次创建的未完成输出。
- Git 查询仅使用本机已有历史，支持分支、作者和时间筛选及提交多选；打包前预览文件范围及缺失项，缺失文件跳过，不产生删除指令。未安装 Git 时仅该入口不可用，其余能力可正常使用。
- 剪贴板分片可乱序加入、增删和替换。重复加入同一归档、同一总片数、同一片号时，自动跳过新片，保留原片并提示，不增加列表项或阻止还原；替换操作若与其他已有片重复，也跳过并保留现有列表。明确替换当前片仍允许重新读取该片内容。继续检查缺片、混包、损坏及密码错误；不同归档的同片号不视为重复。成功后清理本次暂存，失败保留可重试分片，切换工作台页面不丢失已加入的分片。
- 剪贴板还原提供可聚焦的粘贴区域，进入该页后支持直接按 ⌘V（macOS）／Ctrl+V（Windows）连续添加分片；系统粘贴操作走同一导入入口。路径、密码、搜索及其他可编辑输入框保留普通文本粘贴，弹窗和其他页面不触发分片导入。快捷键不把完整分片插入页面；处理中忽略重复触发。
- 记忆上次源目录、输出目录和分片大小；密码不持久化，任务完成或失败后清除。输入文件、输出文件和临时分片不作为工作台资料附件写入完整备份。
- 同一工具一次运行一项处理；展示阶段、进度和当前状态。页面切换不触发重跑，返回后能看到本次结果并打开结果目录或复制路径。
- 延续原工具的运行范围：首版不新增任务队列、运行历史、断点续作或主动取消。正常退出清理临时数据，应用重启不自动续跑上次任务。

### 技术封装

- 沿用工作台模块登记加入工具菜单；增加轻量工具登记契约，将公共元信息与各工具页面、具体输入校验和处理逻辑分开。
- 工具常用项使用稳定工具标识，并同步接入偏好校验、备份恢复和失效入口处理；既有常用项的顺序与引用保持有效。
- 沿用 Electron／Node 桌面基础和现有 ZIP 依赖迁移归档核心，安装后的归档与还原无需另外安装 Python，也不依赖原项目目录。Git 能力继续使用本机 Git。
- 耗时文件处理在独立后台执行单元运行，主进程持有运行状态并处理退出保护；渲染页面只消费状态、进度及短预览，不通过页面状态或 IPC 反复搬运大分片全文。
- 工具执行接口只暴露明确操作，沿用现有 IPC 来源校验、文件选择和路径验证。具体工具的参数与文件处理不集中进首页或全局导航。
- 兼容验证以原项目协议和真实互通为准；保留加密认证、磁盘与粘贴入口的编码差异，以及跨平台路径和文件名保护。

## 验收场景

1. 工具菜单能打开工具目录及 ZIP 文本归档页；首页添加、排序、移除工具常用项后，重启和完整备份恢复均保持正确。
2. 使用包含中文名、二进制、空文件和空目录的样例完整归档后还原；隐藏文件与顶层目录行为符合原工具。
3. 原独立工具生成的分片可由工作台还原，工作台生成的分片可由原工具还原；覆盖多片及非默认分片大小。
4. Git 提交筛选能正确展示所选目录内的文件范围；提交后修改文件再打包，产物包含当前磁盘内容，缺失项清楚显示且不生成删除指令。
5. 剪贴板支持乱序多片、删除、替换与失败重试；重复加入自动跳过并提示，原片与还原状态保留。缺片、混包、损坏或密码错误有明确反馈，不留下伪成功产物。
6. 归档和还原期间切换至首页、台账等页面可正常操作；返回看到连续进度及结果，同一工具不会重复启动；结束前退出被阻止，结束后可正常退出。
7. 输出已存在、无写权限、非法路径及处理失败时不覆盖用户原文件；密码与暂存生命周期符合约定。
8. 使用大文本分片检查页面响应和后台处理，不能将小样例验证等同于 200 MB 上限验证。macOS／Windows 的打包与运行验证分别报告，未实测的平台明确列为验证缺口。
