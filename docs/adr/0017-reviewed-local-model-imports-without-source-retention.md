# 本地模型导入经人工确认，原文与草稿不留存

外部交接资料包含内部敏感信息，因此模型只在本机处理文档并生成供人工核对的台账候选；用户确认后，通过台账与凭据的受控接口保存。模型负责建议，用户逐行确认写入的操作、环境和字段。工作台不持久化导入原文件、原文和未确认的分析草稿，只保存确认后的台账，以放弃软件内长期原文追溯和崩溃后草稿恢复为代价，减少敏感资料的持久副本。

软件和模型允许联网下载，文档内容不能因此发送远端，分析失败不能自动转用云模型。首版只导入明确的密码字段，Token、私钥暂缓；本地仍按既有边界专门保护凭据，普通台账不整体加密。

2026-11-19：用户将首版只新增的规则扩展为逐行新增、跳过或更新。未匹配环境的新增默认系统通用，更新保留原环境。模型比较同批及同系统已有对象，用户确认身份、目标、普通字段差异与环境后，以原有 ID 更新。未选字段、关联及已有凭据保留，原子保存和资料代次约束继续生效。

2026-11-19 补充，已确认的后续设计。内部敏感文件继续仅在本机处理。用户明确标记为可外发的文件，可由用户指定的第三方服务提取候选；已有台账及其字段仍留在本机完成比对。配置远端服务或联网安装模型均不构成文件外发许可，本机分析失败时也不会自动改投远端。这项扩展尚处于设计阶段。

第三方提取首版采用 OpenAI 兼容接口。设备只配置第三方服务时，同名、同地址匹配和指定目标的字段差异均由本机程序计算，用户可通过人工校对完成导入。Ollama 是补充语义相似和迁移建议的可选能力。原有的逐行确认与整批保存边界继续适用。

上述第三方提取边界已接入本机试用构建。主进程按文件会话和已保存服务的版本校验外发许可，远端只承担文件提取；比对用的系统、环境和已有对象仅传给本机规则或就绪的本机模型。

文件内比对与已有台账查重均以当前适用环境为准。两条记录至少有一个共同环境时才比较名称、地址和模型建议。系统通用在每个环境可见，因此参与所有环境的查重。人工改动环境后重新计算比对结果。
