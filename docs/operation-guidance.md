# 操作指引编写与发布规范

状态：已实现并完成隔离 macOS arm64 安装版的代理联合验收。用户在 Q20 确认的内容与发布规则已接入；实际覆盖、测试来源和未验证边界见[任务 11 实施记录](../.scratch/operation-guidance/implementation-11.md)。维护者对拟发布源码的人工核对仍待进行；本地验收不表示已经推送或公开 Release。

依据：[设计访谈](../.scratch/operation-guidance/interview.md)、[ADR 0014](adr/0014-bundle-operation-guides-with-releases.md)、[项目术语](../CONTEXT.md)。

## 1. 目标与范围

维护者通过仓库中的 JSON 与图片配置操作指引，随应用版本分发，用户离线也能查看。首批覆盖全部现有用户功能，按实际操作流程分组；后续每次发布均编写操作说明。首版不提供远程独立更新、应用内编写、逐控件高亮导览或操作完成追踪。

首批范围以[功能覆盖清单](../.scratch/operation-guidance/coverage.md)为准；该清单保留初始范围，并在文末逐项映射已经交付的指引、步骤和核对证据。后续新增或合入的功能必须据实际发布源码更新清单。维护者的构建、提交与发布操作继续在发布文档中说明，不混入普通用户的功能入口。

## 2. 内容分工

| 内容 | 回答的问题 | 维护规则 |
| --- | --- | --- |
| 功能操作指引 | 这项功能如何使用、怎样确认完成？ | 使用稳定标识，随新版本修订当前用法；名称变化不随意重建标识。 |
| 待发布操作说明 | 下一次发布有哪些操作变化？ | 尚不写死正式版本号，关联受影响的功能指引及人工核对记录。 |
| 版本操作指引 | 升级后有哪些变化、接下来怎么操作？ | 发布时绑定实际版本和源码；复用功能指引，保留已发布说明。 |
| 指引提示记录 | 这台设备是否已经展示过版本提示？ | 与业务备份分离；不解释为已阅读、已学会或已完成操作。 |

设置中的功能指引默认展示当前有效用法；历史版本区域保留当时的变化摘要。历史摘要引用当前仍有效的功能入口，已移除功能显示明确说明并停止跳转。发布过的摘要不被新功能正文覆盖；旧版本的完整内容仍可在对应源码中追溯。

首批全量覆盖不等于启动时连续弹出全部教程。功能指引由用户手动查阅；自动弹窗只汇总本次需要提示的版本变化，并提供对应功能指引入口。

首批补齐现有功能，不凭提交标题编造过去版本的操作指引。历史汇总遇到缺口时明确说明可用记录范围，不能将缺失记录当作“无新增操作”。

## 3. 功能指引的统一写法

每篇必须包含以下内容；简单功能可以简写。不适用时写出原因，不用空字符串或空数组冒充已经编写。

| 字段 | 编写要求 |
| --- | --- |
| 用途 | 一两句话说明用户能完成什么，不介绍实现细节。 |
| 准备条件 | 需要的对象、文件、权限、解锁状态与平台条件；无特殊条件时明确写出。 |
| 功能入口 | 与实际界面文案一致，说明从哪里进入；配置引用预设入口标识。 |
| 操作步骤 | 每步只写一个主要动作，并给出可观察结果；注明可选分支和取消路径。 |
| 完成结果 | 用户如何判断操作完成、结果在哪里；不能把下载完成写成安装成功。 |
| 常见问题 | 具体症状、可能原因、可执行的下一步；确实不适用时说明原因。 |

正文用简体中文及当前领域术语。备份与导出、主密码与备份密码、任务与运行作业必须区分；与当前实现不一致的文案应记录为问题，不替产品实现作承诺。

截图按需提供，不要求每步配图。使用隔离示例资料，不含真实密码、Token、私钥、个人路径或业务地址；图片附替代文字，文字步骤必须能独立表达关键操作。图中按钮、主题和布局须与描述匹配；不要用将要实现的截图描述已经发布的功能。

完整流程可按子任务拆分，但不可仅写功能概述而缺少可执行步骤。功能覆盖清单逐项关联到指引或具体步骤，避免“一篇设置说明”被误认为已经覆盖所有设置。

## 4. 配置契约

维护者使用[功能模板](operation-guidance/feature.template.json)、[有操作变化的发布模板](operation-guidance/release-changed.template.json)和[无新增操作的发布模板](operation-guidance/release-none.template.json)。这些文件是编写模板，包含占位文字，不直接进入安装包。

### 功能指引

- `schemaVersion` 标识配置格式；未知格式作为无效内容降级，不执行猜测性解析。
- `id` 为稳定的功能指引标识；`revision` 记录内容修订，不改变功能身份。
- `title`、`purpose`、`prerequisites`、`entry`、`steps`、`completion`、`faq` 对应统一模板。
- `entry.target` 引用受控入口登记表；展示位置由 `placements` 引用预设位置。配置不能携带 shell、脚本、任意 HTML、文件打开命令或任意导航地址。
- `content/guidance/manifest.json` 列出首批必备的稳定功能标识；每项正文使用 `features/<标识>.json`。新增或拆分首批正文时同步维护清单。它用于发现未被当次发布说明引用的缺文件，清单本身缺失或损坏也只产生警告。
- 步骤具有稳定 `id`、动作文字和结果说明，可附仓库内图片引用及替代文字。步骤顺序由配置顺序决定。
- `platforms` 表示内容适用平台；平台限定步骤明确标注。macOS 专属安装说明不能直接当作 Windows 操作步骤。

### 待发布说明

- `operationChange` 明确为 `changed` 或 `none`。空文件、缺文件、格式错误属于未知，不能推断为 `none`。
- `changed` 提供用户摘要及 `changes`，每项具有稳定标识、变化说明与对应 `guideIds`。以人工列出的用户可见操作变化核对覆盖，不声称机器能从全部源码自动证明没有遗漏。
- `none` 明确写出“无新增操作”及 `noOperationReason`，`changes` 为空。修复本身改变了操作流程时仍属于 `changed`。
- `review` 记录实际核对人员、时间、版本或源码、环境、检查结果、证据与已知缺项；未验证就写未验证，不自动填写通过。
- 不在配置里放本机 Git 凭据、资料路径或用户业务数据。审核人字段不用于覆盖 Git 提交身份。

### 分发与加载

内容、受支持图片和版本历史进入应用自身资源，不能依赖开发机路径、网络图片或在线文档才能阅读。所有路径限制在本次指引资源内；未知入口和非法图片路径不可执行或读取。

配置文件分别容错加载，避免一篇无效 JSON 使整个指引模块或应用构建崩溃。不能将全部 JSON 作为必须解析成功的静态源码导入后，再宣称“内容问题不会阻止发布”。格式未知、内容不完整的条目给出警告并跳过；缺图时保留有效文字和图片替代说明。

## 5. 查阅与弹窗

- 功能附近提供“使用指引”，设置提供统一查阅入口。密集工具栏可以用现有菜单承载入口，入口文字及图标名称保持一致。
- 采用统一图文步骤弹窗，提供步骤位置、上一步／下一步、明确关闭及“前往功能”。长内容滚动时关闭和主要操作仍可到达。
- 复用现有 Dialog、主题变量和无拖拽区域，验证 Esc、关闭按钮、键盘焦点和关闭后焦点返回；尊重减少动态效果、高对比度与减少透明度设置。
- “前往功能”仅导航，不自动导出、删除、恢复、解锁或安装。无适用对象时进入可选择对象的页面，不擅自选用过期背景；需要解锁时沿用功能自己的入口要求。
- 台账类入口携带受控分类，进入访问入口、账号、服务器、数据库／中间件、应用部署或运行维护对应清单；不携带历史选中对象，也不直接打开编辑框。
- 跳转前走现有保存链路。保存失败保留用户输入及当前页面，提供重试，不伪装成导航成功。
- 不在恢复代次切换、安装冻结或其他阻止导航的阶段强行打开功能；相关异步结果必须遵守现有代次校验。

## 6. 自动提示与设备记录

| 场景 | 行为 |
| --- | --- |
| 首次启用指引 | 只考虑当前版本；有操作变化则在合适时机提示，不追溯全部历史。 |
| 后续单次或跨版本升级 | 汇总升级范围内尚待提示的操作变化，同一功能合并介绍并引用当前有效指引。 |
| 目标版本无变化，中间版本有变化 | 仍汇总提示一次；是否提示取决于整个升级范围。 |
| 整个范围明确无操作变化 | 不自动弹窗，历史说明仍可手动查阅。 |
| 存在待保存内容、其他弹窗或安装／恢复流程 | 暂缓提示，不抢占焦点，不将等待状态记成已经提示。 |
| 弹窗实际成功显示 | 记录该次覆盖的版本已提示；关闭、Esc、重启后不重复自动展示。 |
| 手动重新打开 | 始终允许查看有效内容，不重置自动提示记录。 |
| 恢复旧业务备份 | 保留当前设备的提示记录，不恢复成旧状态。 |
| 换设备或确实没有有效记录 | 按首次启用处理，不假装知道旧设备阅读历史。 |
| 没有任何有效内容 | 不弹空窗口；手动入口简短说明暂不可用。 |

自动提示等待主界面和当前页面就绪、正在编辑的内容完成保存；用户仍在连续输入时继续等待，不因一次自动保存完成就抢走焦点。检查时机须与实际弹窗打开协调，避免“检查通过后另一个弹窗先打开”的竞争。正常工作期间不以后台轮询反复尝试抢焦点，不能为展示指引擅自关闭其他弹窗。

提示记录由主进程以设备偏好管理，保存在业务资料代次、数据库及完整备份之外；写入失败不能冒充记录成功。版本状态需要区分已启动、待提示和已提示，不能仅凭版本号变化就提前消费提示；已显示过的版本也不能因降级后再次升级而反复提示。记录损坏时只采用首次启用规则，不追溯全部历史。

这些状态不是阅读进度，不向产品界面显示虚假的“学习完成率”，也不追踪用户是否真的执行指引步骤。

## 7. 每次发布的编写流程

1. 根据实际发布源码与上一个正式版本的差异，列出用户可见操作变化。首个接入版本同时完成全部现有功能的覆盖清单。
2. 更新对应功能指引；为本次发布填写待发布操作说明。无操作变化也必须填写原因。
3. 在隔离示例资料中预览指引，按步骤核对入口、结果、图片和取消路径，记录实际结果及已知缺项。
4. 将源码、指引、图片和核对记录一并提交到计划发布的远端源码。沿用本地 Git 身份及中文提交要求；未推送资料不进入当前远端发布流程。
5. 本地发布预检输出指引警告，展示计划实际纳入的内容；只读预览不改工作区、不创建提交或标签。
6. 在原有发布准备阶段把待发布内容绑定到选定的正式版本及源码，生成该版本记录与打包输入；与版本文件一起进入同一次版本准备，防止源码与说明错配。
7. GitHub Actions 复用同一规则输出警告和汇总，构建时只打包该 tag 对应的内容；应用内与 GitHub 发布摘要由这份数据生成。
8. 保存发布绑定、构建及内容核对证据，发布后保留该版本说明。后续修订随新版本分发，不覆盖已发布资产或标签。

本流程的指引检查只提醒，不增加新的发布确认卡点；原有发布确认、源码身份校验、构建、测试、包校验与资产检查照常工作。允许带着指引缺项发布，不等于缺项已经合规或检查通过。

### 版本与源码绑定

待发布内容不预占版本号。实际准备时记录正式版本、tag 和业务源码 SHA；构建记录再保存 tag 指向的版本提交 SHA。不得尝试把一个提交自身的 SHA 写回同一个提交。

失败版本占用 tag 后，只有源码和内容仍对应时才能复用已有审阅结果；转用新版本号或更换源码必须重新生成绑定并确认差异。已有 tag 的重跑读取该 tag 内容，不读取后来变动的待发布文件。具体文件位置和生成命令在实现中确定，不复用未确认的本地发布脚本草稿。

### GitHub 发布正文

按“用户更新摘要 → 操作说明／应用内查阅入口 → 技术提交明细 → 来源与产物”的顺序组织。同源指同一待发布内容经实际版本绑定后生成，不是复制两份独立手写说明。

可链接到对应 tag 中的仓库指引文件，并说明安装后从设置查阅；链接沿用仓库现有访问权限，不声称私有仓库内容可以匿名访问。不为此引入应用 URL 协议。没有完整指引时如实写“暂未提供完整操作指引”，保留有效摘要和技术提交明细，不能自动写成“无新增操作”。

## 8. 非阻断检查与异常降级

| 问题 | 发布检查 | 应用表现 |
| --- | --- | --- |
| 文件缺失、JSON 无效、未知格式 | 警告文件、位置、原因与修正办法 | 跳过无效条目，应用正常运行。 |
| 必填内容缺失、占位文字、重复标识 | 警告具体条目与字段 | 无法确定完整有效条目时不展示，不随意选择重名内容。 |
| 引用不存在的指引或已失效入口 | 警告引用关系 | 保留可用说明；无效入口禁用并说明原因。 |
| 图片缺失、格式不支持或路径越界 | 警告图片引用 | 不读取非法路径，保留文字及有效替代说明。 |
| 已列出的操作变化没有对应指引 | 警告缺项 | 展示有效部分，不谎称全部覆盖。 |
| 缺少发布说明或人工核对记录 | 警告未提供或未核对 | 不显示虚假“无新增操作”或“已核验”。 |
| 整份版本内容无法展示 | 警告本次没有有效版本指引 | 不自动弹空窗口，手动查看给出暂不可用说明。 |

报告包含警告代码、文件和字段、问题、建议处理方式；本地终端和 GitHub Actions 汇总保持相同语义。检查器应能收集多项问题后统一报告，内容问题不以非零退出码使发布失败。

有效内容的选择和同源生成也要容错；不能只让单独的检查步骤忽略退出码，却在后续生成或打包阶段因同一份无效内容阻断发布。真正的代码构建、包安全校验等失败仍按现有发布流程处理，不一律吞掉。

## 9. 验收与证据

实现后以 macOS 安装版和隔离 `CLEVER_WORKBENCH_DATA_DIR` 为主要入口；不得把用户真实资料作为测试数据，也不得把开发运行直接写成安装包验收通过。

- 内容：全量覆盖清单逐项关联有效步骤；模板字段、领域术语、平台、入口和图片与实际界面一致。
- 离线：断网后功能指引和随包版本历史仍可阅读，图片来自安装包，没有开发机路径依赖。
- 生命周期：首次启用、连续升级、跨版本升级、无变化范围、等待期间重启、成功展示后重启、手动重开、降级再升级均符合提示规则。
- 设备状态：恢复旧业务备份不回退提示记录；新设备按首次启用处理；读取或写入失败不虚报成功。
- 交互：其他弹窗、未保存输入、保存失败、恢复代次变化和安装冻结不会被指引打断或绕过；“前往功能”不执行业务副作用。
- 异常：单篇无效 JSON 不破坏其他指引；缺图、无效引用和无有效内容能够降级；本地发布、CI 汇总、正文生成及打包均允许内容警告继续。
- 视觉：浅色／深色、正常／窄窗口、长内容、Esc、焦点返回和辅助外观设置可用；原生鼠标验证关闭按钮和窗口拖拽区域。
- 来源：实际版本、业务源码、tag、构建内容和 GitHub 摘要一致；失败版本重跑不混入新的待发布内容。

人工核对记录填写验证环境、版本或源码、对应指引与步骤、结果、证据和遗留项。结果可以是通过、失败、未验证或不适用；不适用说明原因。首批全量内容与展示机制分别记录完成情况，不能用机制通过代替全部指引验收。

上述机制、26 组首批正文及本地发布检查已有[逐项覆盖映射](../.scratch/operation-guidance/coverage.md)和[隔离安装版验收](../.scratch/operation-guidance/implementation-11.md)。真实 GitHub Actions、远程 Release、自动安装替换、生产系统钥匙串授权与其他平台仍须按实际执行结果另行记录。
